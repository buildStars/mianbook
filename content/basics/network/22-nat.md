# NAT 是什么？私有 IP 是怎么访问公网的？

::: tip 一句话回答
NAT（网络地址转换）在路由器上**改写 IP 包的地址**，让内网的私有 IP 共用少量公网 IP 上网。最常见的是 **NAPT**：出去时把"私有 IP:端口"换成"公网 IP:端口"并记进**映射表**，回来时按映射表换回去。从内往外改源地址叫 **SNAT**，从外往内改目的地址叫 **DNAT**（端口映射）。NAT 让外部无法主动连进内网，给 P2P 带来麻烦，需要 **STUN 打洞**或 **TURN 中继**。
:::

## 详细解析

### 私有地址和 NAT 的由来

IPv4 只有约 43 亿个地址，不够每台设备分一个。RFC 1918 划出三段私有地址，可以在任何内网重复使用，但不能在公网上路由：

| 地址段 | CIDR | 常见场景 |
| --- | --- | --- |
| `10.0.0.0` ～ `10.255.255.255` | `10.0.0.0/8` | 企业内网、云上 VPC |
| `172.16.0.0` ～ `172.31.255.255` | `172.16.0.0/12` | 企业内网、Docker 默认网段 |
| `192.168.0.0` ～ `192.168.255.255` | `192.168.0.0/16` | 家用路由器 |

私有地址出不了公网，所以出口处要有一台设备把它换成公网地址，这就是 NAT。CIDR 的写法见 [IP 地址分类和子网掩码](/basics/network/23-subnet)。

### NAPT：靠端口区分内网主机

只做 IP 一对一替换的叫静态 NAT，一个公网 IP 只能对应一台内网主机，意义不大。实际用的基本是 NAPT（也叫 PAT，Linux 里叫 MASQUERADE），同时改 IP 和端口：

```text
内网主机 192.168.1.10:50001 ──► 访问 93.184.216.34:443
路由器出口公网 IP 203.0.113.5

映射表（路由器维护）：
协议  内网地址              公网地址             远端地址
TCP   192.168.1.10:50001  ⇄  203.0.113.5:40001  93.184.216.34:443
TCP   192.168.1.11:50001  ⇄  203.0.113.5:40002  93.184.216.34:443

出去：源地址 192.168.1.10:50001 改成 203.0.113.5:40001
回来：目的地址 203.0.113.5:40001 查表改回 192.168.1.10:50001
```

两台主机用了同一个内网端口也没关系，路由器给它们分配不同的公网端口。改了 IP 和端口后，IP 头和 TCP/UDP 头的校验和也要重新计算。映射项有超时时间，TCP 连接关闭或 UDP 一段时间没流量后就会被清掉。

### SNAT 和 DNAT

- **SNAT**（源地址转换）：改源地址，用于内网访问外网。家用路由器、云上的 NAT 网关做的就是这个
- **DNAT**（目的地址转换）：改目的地址，用于外网访问内网服务。路由器上的"端口映射"、Docker 的 `-p 8080:80`、Kubernetes Service 的转发规则，底层都是 DNAT。负载均衡的整体思路见 [反向代理和负载均衡](/basics/network/20-reverse-proxy)

### NAT 对 P2P 的影响

NAT 只有内网先发包才会建映射，外部主机没法主动连一个 NAT 后面的地址。两个都在 NAT 后面的客户端要直连（例如 WebRTC 音视频），常见做法：

1. **STUN**：客户端问公网上的 STUN 服务器"你看到的我是哪个 IP 和端口"，拿到自己的公网映射地址
2. 双方通过信令服务器交换这些地址，同时给对方发包，各自的 NAT 上都建立了映射，这就是 **UDP 打洞**
3. 如果 NAT 对每个目的地址分配不同的端口（对称型 NAT），STUN 拿到的端口对方用不上，打洞会失败，只能走 **TURN** 服务器中继，所有流量经它转发，延迟和带宽成本更高

WebRTC 里的 ICE 框架会把这几种候选地址都收集起来，按优先级逐个尝试。

## 代码示例

```bash
# Linux 做 NAT 网关：开启转发
sudo sysctl -w net.ipv4.ip_forward=1

# SNAT：内网 192.168.1.0/24 从 eth0 出去时，源地址换成 eth0 的地址
sudo iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o eth0 -j MASQUERADE

# DNAT：访问本机 8080 端口的流量转给内网 192.168.1.20:80
sudo iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 8080 -j DNAT --to-destination 192.168.1.20:80

# 查看当前的连接跟踪表（NAT 映射记录在这里，需要 conntrack 工具）
sudo conntrack -L
```

## 面试官可能追问

::: details NAT 算不算一种安全措施？
它客观上挡住了外部主动发起的连接，但这不是它的设计目的，不能代替防火墙。内网主机主动发出的连接，回包照样能进来；做了端口映射的服务也会直接暴露。
:::

::: details 有了 IPv6 还需要 NAT 吗？
IPv6 地址足够多，每台设备都能有全局地址，设计上不需要 NAT。安全隔离交给防火墙的有状态规则来做。实际上过渡期仍有 NAT64 这类方案，让纯 IPv6 网络访问 IPv4 资源。
:::

::: details 一个公网 IP 最多能支撑多少连接？
NAPT 用端口区分映射，单个协议的端口号只有 16 位，可用端口有上限。但映射通常和远端地址一起区分，访问不同目标时端口可以复用，所以实际并发取决于 NAT 设备的实现和连接跟踪表大小。大量连接打到同一个目标时容易出现端口耗尽。
:::

## 易错点

- `172.16.0.0/12` 是 `172.16` 到 `172.31`，不是整个 `172.x.x.x`
- 家用路由器做的主要是 NAPT，改 IP 的同时也改端口，不是单纯的 IP 替换
- SNAT 用在出方向、改源地址；DNAT 用在入方向、改目的地址，别记反
- STUN 不转发数据，只告诉客户端自己的公网地址；转发数据的是 TURN
