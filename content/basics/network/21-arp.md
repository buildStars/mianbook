# ARP 协议的工作原理是什么？跨网段通信时怎么找到 MAC 地址？

::: tip 一句话回答
ARP 用来在**同一个局域网**里根据 IP 地址查 MAC 地址：先查本机 **ARP 缓存**，查不到就**广播**一个 ARP 请求，目标主机用**单播**回复自己的 MAC。跨网段时，主机不会去查对方的 MAC，而是查**默认网关**的 MAC，把帧交给网关，由路由器逐跳转发。ARP 没有认证机制，所以有 **ARP 欺骗**的风险。
:::

## 详细解析

### 为什么需要 ARP

以太网上传数据靠的是帧，帧头里要填目的 MAC 地址；而上层只知道目标的 IP。ARP 就是把"IP → MAC"这一步补上的协议。它工作在网络层和数据链路层之间，报文直接封装在以太网帧里（EtherType 是 `0x0806`），不经过 IP。分层的整体关系见 [OSI 七层模型和 TCP/IP 四层模型](/basics/network/02-network-layers)。

### 一次完整的解析过程

假设主机 A（`192.168.1.10`）要给同网段的 B（`192.168.1.20`）发数据：

1. A 查本机 ARP 缓存，有 `192.168.1.20` 的记录就直接用
2. 没有就发 ARP 请求：目的 MAC 是广播地址 `ff:ff:ff:ff:ff:ff`，内容是"谁是 192.168.1.20？请告诉 192.168.1.10"，请求里带着 A 自己的 IP 和 MAC
3. 局域网里所有主机都会收到。IP 不匹配的直接丢弃；B 发现问的是自己，先把 A 的映射记进自己的缓存
4. B 用**单播**回复 ARP 应答，告诉 A 自己的 MAC
5. A 把结果写入缓存，填好帧头发出数据

缓存条目有老化时间，过期后要重新解析，避免主机换网卡或换 IP 后一直用旧记录。

### 跨网段：查的是网关的 MAC

A 发送前先用子网掩码判断目标 IP 是不是同一网段（计算方法见 [子网掩码和 CIDR](/basics/network/23-subnet)）：

```text
目标同网段  → ARP 解析目标主机的 MAC，直接发
目标不同网段 → ARP 解析默认网关的 MAC，帧发给网关

A ──帧(目的MAC=网关)──► 路由器 ──帧(目的MAC=下一跳)──► ... ──► B
     IP 头：源 A，目的 B（全程不变，经过 NAT 除外）
```

路由器收到后拆开看 IP 头，查路由表决定下一跳，在出口网络上再做一次 ARP，换上新的源 MAC 和目的 MAC 继续转发。所以 MAC 地址只在一跳内有效，IP 地址才是端到端的。

### 免费 ARP

免费 ARP（Gratuitous ARP）是主机主动广播一个"询问自己 IP"的 ARP 包，不是为了查别人。常见用途：

- **检测 IP 冲突**：如果有人回应，说明这个 IP 已被别人占用
- **通告 MAC 变化**：主备切换时虚拟 IP 漂到新机器上（例如 keepalived 的 VRRP），新主机发免费 ARP，让交换机和其他主机立刻更新缓存，否则流量还会发到旧机器

### ARP 欺骗和防护

ARP 是无状态、无认证的：很多系统收到应答就会更新缓存，不管自己有没有发过请求。攻击者可以冒充网关不停发伪造应答，让受害者把发往网关的流量交给自己，形成中间人攻击，或者直接造成断网。

防护思路：

- 关键主机上**静态绑定**网关的 IP 和 MAC
- 交换机开启 **DAI**（动态 ARP 检测），配合 DHCP Snooping 记录的合法绑定表，丢弃不匹配的 ARP 包
- 上层用 **HTTPS / TLS** 加密，即使流量被劫持也看不到、改不了内容

## 代码示例

```bash
# 查看本机 ARP 缓存（Linux 推荐用 ip neigh，arp 命令是老工具）
ip neigh show
# 192.168.1.1 dev eth0 lladdr aa:bb:cc:dd:ee:ff REACHABLE

# 删除某条缓存，下次通信时会重新解析
sudo ip neigh del 192.168.1.1 dev eth0

# 抓 ARP 包观察请求和应答
sudo tcpdump -i eth0 -n arp
```

## 面试官可能追问

::: details 为什么 ARP 请求用广播，应答用单播？
请求方不知道目标的 MAC，只能广播让所有人都收到。应答方从请求里已经拿到了请求方的 MAC，直接单播回去就行，不必打扰其他主机。
:::

::: details 交换机的 MAC 地址表和 ARP 缓存有什么区别？
ARP 缓存在主机和路由器上，记录的是"IP → MAC"，属于三层到二层的映射。交换机的 MAC 地址表记录的是"MAC → 端口"，交换机根据收到帧的源 MAC 学习，用来决定帧从哪个口转发，它不关心 IP。
:::

::: details 什么是代理 ARP？
路由器替另一个网段的主机回答 ARP 请求，把自己的 MAC 返回给请求方。这样即使主机的掩码配错、把远端地址当成本网段，流量也能交给路由器转发。它能掩盖配置问题，现在多数网络默认不开。
:::

::: details IPv6 还用 ARP 吗？
不用。IPv6 用邻居发现协议（NDP），基于 ICMPv6，用组播代替广播，地址解析、重复地址检测、路由器发现都由它完成。
:::

## 易错点

- 跨网段通信时，主机 ARP 解析的是**网关**的 MAC，不是目标主机的 MAC
- ARP 报文直接封装在以太网帧里，不是 IP 包，也不是 UDP
- 一路转发下来 MAC 地址每跳都会变，IP 地址一般不变，别把两者说反
- 免费 ARP 不是"不需要应答的普通 ARP"，它查的是自己的 IP，目的是冲突检测和缓存更新
