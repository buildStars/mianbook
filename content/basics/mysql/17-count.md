# count(*)、count(1)、count(字段) 有什么区别？大表 count 很慢怎么办？

::: tip 一句话回答
`count(*)` 和 `count(1)` 都是**统计行数**，结果一样，InnoDB 对它们的处理方式也一样，没有性能差别。`count(字段)` 统计的是**该字段不为 NULL 的行数**，语义不同。InnoDB 因为 MVCC 不存总行数，`count(*)` 要真的去扫描，优化器会挑**最小的二级索引**来扫。大表要快，就不要每次实时数：用 Redis 或计数表维护计数，或者接受近似值。
:::

## 详细解析

### 三种写法的语义

| 写法 | 统计什么 | 说明 |
| --- | --- | --- |
| `count(*)` | 所有行 | SQL 标准写法，推荐 |
| `count(1)` | 所有行 | 1 永远不是 NULL，等价于 `count(*)` |
| `count(主键)` | 所有行 | 主键非空，结果相同，但要读出主键值 |
| `count(字段)` | 字段非 NULL 的行 | 字段允许 NULL 时结果可能更少 |
| `count(DISTINCT 字段)` | 去重后的非 NULL 值个数 | 要去重，更慢 |

```sql
-- 假设 users 有 3 行，其中 1 行 email 为 NULL
SELECT count(*), count(1), count(email) FROM users;
-- 3, 3, 2
```

`count(字段)` 如果字段允许 NULL，引擎要逐行判断；字段上没有索引时只能扫主键索引读整行，更慢。

### 为什么 InnoDB 不存总行数

在 [MVCC](/basics/mysql/06-mvcc) 下，事务 A 刚插入还没提交的行，事务 B 看不到；可重复读下老事务看到的也是旧快照。同一时刻不同事务"应该看到的行数"不一样，所以没法存一个全局计数，只能按当前事务的读视图一行行判断。MyISAM 只有表锁才能存（见 [InnoDB 和 MyISAM](/basics/mysql/16-innodb-myisam)）。

### 优化器怎么数

数行数不需要读整行，任何一个包含所有行的索引都可以。二级索引叶子只存索引列和主键，比聚簇索引（叶子是整行）小得多，扫描的页更少。所以 `count(*)` 会优先选**最小的二级索引**，没有二级索引才扫主键索引。用 `EXPLAIN` 能看到 `key` 列选了哪个索引。

### 大表 count 慢的方案

| 方案 | 做法 | 注意 |
| --- | --- | --- |
| Redis 计数 | 增删数据时 `INCR` / `DECR` | 和数据库不在一个事务里，会有短暂不一致，宕机可能丢；要定期校准 |
| 计数表 | 单独一张表存计数，和业务写入放在**同一个事务**里更新 | 准确；但热点行会成为写瓶颈，可以拆成多行再求和 |
| 近似值 | `SHOW TABLE STATUS` 的 `Rows`，或 `information_schema.TABLES` 的 `TABLE_ROWS` | 是统计信息里的估算值，误差可能很大，只适合"大约多少" |
| `EXPLAIN` 估算 | 看 `rows` 列 | 同样是估算，适合带条件时粗略判断 |
| 产品层面 | 分页只显示"下一页"，或总数显示为"1 万+" | 往往是最省事的方案 |

带条件的 count（如某个用户的订单数）要靠合适的索引让扫描范围变小，或者按维度维护计数。

## 面试官可能追问

::: details 计数表和 Redis 计数怎么选？
要求准确、并发不太高，用计数表，和业务写在同一个事务里就不会不一致。并发很高、能容忍短暂误差，用 Redis，再加定时任务用 `count(*)` 校准。
:::

::: details 计数表在高并发下有什么问题，怎么解决？
所有写都更新同一行，会在这一行的行锁上排队。可以把一个计数拆成 N 行（比如 10 行），每次随机更新其中一行，读的时候 `SUM`，用读的一点代价换写的并发。
:::

::: details 为什么 count(主键) 不一定比 count(*) 快？
`count(主键)` 要把主键值读出来再判断是否为 NULL，`count(*)` 只需要知道这一行存在。两者都可能选择最小的二级索引来扫，`count(*)` 不会更慢，所以直接用 `count(*)`。
:::

## 易错点

- 认为 `count(1)` 比 `count(*)` 快，这是误传，InnoDB 里两者一样
- `count(字段)` 会跳过 NULL，拿它统计总行数结果可能偏少
- `TABLE_ROWS` 是估算值，不能当作精确的行数展示
