# CHAR 和 VARCHAR 有什么区别？VARCHAR(100) 和 VARCHAR(10) 存短字符串有区别吗？

::: tip 一句话回答
`CHAR(M)` 是**定长**，不足 M 个字符时用空格补齐，读出时去掉尾部空格；`VARCHAR(M)` 是**变长**，只存实际内容，再加 1 或 2 个字节的**长度前缀**。M 都是**字符数**，占多少字节还要看字符集。存同样的短字符串，`VARCHAR(100)` 和 `VARCHAR(10)` 在磁盘上占用基本一样，但排序、内存临时表等场景可能按**定义的最大长度**分配内存，所以长度不要随手定得很大。
:::

## 详细解析

### 定长和变长

| 维度 | CHAR(M) | VARCHAR(M) |
| --- | --- | --- |
| 存储 | 固定长度，不足补空格 | 实际长度 + 长度前缀 |
| M 的范围 | 0～255 个字符 | 受行大小 65535 字节限制 |
| 尾部空格 | 读出时去掉 | 原样保留 |
| 适合 | 长度固定的值：MD5、国家代码、手机号 | 长度不定的值：用户名、标题 |

InnoDB 对变长字符集（如 utf8mb4）的 CHAR 列有个细节：它至少占 M 个字节，实际内容更长时按实际字节存，并不是总按 M × 4 字节分配。

长度前缀的规则：这一列**最大可能字节数**不超过 255，用 1 个字节；超过 255，用 2 个字节。

```text
utf8mb4 一个字符最多 4 字节
VARCHAR(50)  最大 200 字节  -> 1 字节长度前缀
VARCHAR(64)  最大 256 字节  -> 2 字节长度前缀
```

### 字符数和字节数

M 是字符数，不是字节数。`VARCHAR(10)` 在 utf8mb4 下能存 10 个汉字，也能存 10 个 emoji。算行大小上限和索引长度上限时，按"字符数 × 字符集最大字节数"计算，所以 utf8mb4 下 VARCHAR 能定义的最大 M 会比 latin1 小很多。

### 尾部空格

```sql
CREATE TABLE t (c CHAR(5), v VARCHAR(5));
INSERT INTO t VALUES ('ab  ', 'ab  ');
SELECT CONCAT('[', c, ']'), CONCAT('[', v, ']') FROM t;
-- [ab]  [ab  ]
```

CHAR 存的时候补空格、读的时候去空格，所以原值末尾的空格也一起丢了。需要保留尾部空格的数据不要用 CHAR。

### VARCHAR(100) 和 VARCHAR(10) 的区别

存 "abc" 时，两者在磁盘上都是"长度前缀 + 3 个字节"，空间一样。区别在定义的长度会被用于估算内存：

- **排序**：`ORDER BY` 要把数据放进排序缓冲区。较早的版本按定义长度估算每行大小，定义越长一次能放的行越少，更容易用到磁盘临时文件；新版本会把变长字段紧凑存放，影响小了很多，但定义过长仍然会影响内存估算
- **内存临时表**：旧版本的内存临时表按定长存储 VARCHAR，`VARCHAR(1000)` 的每一行都占满最大长度，很快超过上限转成磁盘临时表。MySQL 8.0 的 TempTable 引擎对变长做了改进，但定义长度仍会影响内存估算
- **以后改长度**：扩大 VARCHAR 长度时，如果长度前缀的字节数不变，可以原地修改；从 1 字节跨到 2 字节就要重建表（见 [Online DDL](/basics/mysql/15-online-ddl)）

所以按业务真实上限定义长度，再留一点余量，不要统一写 `VARCHAR(255)` 或更大。

## 面试官可能追问

::: details DATETIME 和 TIMESTAMP 有什么区别？
TIMESTAMP 占 4 字节，范围是 1970 到 2038 年，存储时按会话时区转成 UTC，读取时再转回来，适合跨时区。DATETIME 占 5 字节（带小数秒再多几字节），范围是 1000 到 9999 年，存什么读什么，与时区无关。新项目担心 2038 问题时多用 DATETIME，时区在应用层统一处理。
:::

::: details 手机号用 CHAR(11) 还是 BIGINT？
一般用 CHAR 或 VARCHAR。手机号不参与计算，可能有国际区号、前导 0 或 `+` 号，用整数会丢信息。只存国内号码时 CHAR(11) 就够了。
:::

::: details 长文本该用 VARCHAR 还是 TEXT？
能确定上限、长度不太大的用 VARCHAR，可以有默认值、可以完整建索引。很长的内容用 TEXT，它可能存在行外，不能有默认值（较新版本支持表达式默认值），建索引必须指定前缀长度。查询时避免 `SELECT *` 把大字段一起读出来。
:::

## 易错点

- `VARCHAR(100)` 的 100 是字符数，不是字节数
- 认为 VARCHAR 长度定多大都一样，忽略了排序和临时表的内存估算
- CHAR 会去掉尾部空格，存带尾部空格的值会丢数据
