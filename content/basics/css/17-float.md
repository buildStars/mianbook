# 浮动是什么？为什么要清除浮动？

::: tip 一句话回答
`float` 让元素**脱离普通文档流**，向左或向右移动，直到碰到包含块的边缘或另一个浮动元素；后面的**文字和行内内容会环绕**它。浮动元素不参与父元素的高度计算，子元素全部浮动时父元素**高度塌陷**为 0，背景和边框包不住内容，后面的元素也会跑上来。清除办法有两类：在浮动元素后面放一个 **`clear: both`** 的块（clearfix 伪元素写法），或者让父元素**形成 BFC**，其中 **`display: flow-root`** 没有副作用。现在做布局用 Flex 和 Grid，浮动只适合**图文环绕**。
:::

## 详细解析

### 浮动元素的表现

- **只让文字让位**：后面的块级盒子会当浮动元素不存在，照常占据它的位置（背景会钻到浮动元素下面），只是里面的**行盒变短**，文字绕开浮动元素排列。这就是"环绕"的原理
- **块级化**：浮动后 `display` 的计算值会变，`inline`、`inline-block` 变成 `block`，`inline-flex` 变成 `flex`。所以给 `span` 加 `float` 后可以直接设宽高
- **宽度收缩**：没有设置宽度的浮动元素，宽度按内容收缩，不再占满一行
- **依次排列**：多个左浮动元素从左往右排，一行放不下就往下换；后面的浮动元素不会排得比前面的更高
- **自身是 BFC**：浮动元素会把自己的浮动子元素包含在高度里
- **flex、grid 子项上无效**：这两种布局里 `float` 和 `clear` 都不起作用

和绝对定位比，浮动元素"脱离了流，但还影响流"：它会挤开后面的文字；绝对定位元素完全不影响其他内容。

### 高度为什么会塌陷

普通块级元素的 `height: auto` 只由**普通流**里的子元素撑开，浮动子元素不算在内。所以：

```text
父元素 .list（子元素都左浮动，高度为 0，边框缩成一条线）
┌───────────────────────────────┐
└───────────────────────────────┘
 ┌─────┐ ┌─────┐
 │  A  │ │  B  │  后面的段落跑上来，文字挤在 B 的右边
 └─────┘ └─────┘
```

常见后果：父元素的背景、边框包不住子元素；后面的兄弟元素顶上来，它的文字挤到浮动元素旁边；想给父元素设的下边距也和预期的位置对不上。

### 清除浮动的几种方法

| 方法 | 写法 | 原理 | 代价 |
| --- | --- | --- | --- |
| 末尾加空元素 | 最后放一个 `clear: both` 的 `div` | 空元素被推到浮动元素下方，把父元素撑开 | 多了一个没有语义的标签 |
| clearfix | 父元素的 `::after` 设 `clear: both` | 同上，用伪元素代替空标签 | 占用了 `::after` |
| `overflow: hidden / auto` | 写在父元素上 | 父元素形成 BFC，高度包含浮动子元素 | 溢出的阴影、下拉菜单会被裁掉 |
| `display: flow-root` | 写在父元素上 | 专门用来创建 BFC | 基本没有，只有很老的浏览器不支持 |
| 父元素也浮动 | `float: left` | 浮动元素自身是 BFC | 问题转移给了上一层 |

`clear` 只对**块级元素**生效，所以 clearfix 里的伪元素要写 `display: block`（或 `table`）。BFC 为什么能包含浮动，见 [BFC](/basics/css/02-bfc)。

```css
/* clearfix：父元素加上这个类 */
.clearfix::after {
  content: "";
  display: block;
  clear: both;
}

/* 现代写法：一行，同时防止子元素的 margin 穿透到父元素外面 */
.list {
  display: flow-root;
}
```

### clear 的作用范围

`clear: left / right / both` 让元素移动到**前面**的左浮动、右浮动或全部浮动元素的下方，只看**同一个 BFC** 里排在它前面的浮动元素。它只影响自己的位置：想让父元素包住浮动的子元素，给父元素写 `clear` 没有用。

## 代码示例

浮动现在的主要用途是图文环绕，配合 `shape-outside` 还能让文字沿着形状排列：

```html
<style>
  .article {
    display: flow-root; /* 包住浮动的头像，下一段内容不会钻上来 */
  }
  .avatar {
    float: left;
    width: 120px;
    height: 120px;
    margin: 0 16px 8px 0;
    border-radius: 50%;
    shape-outside: circle(50%); /* 只对浮动元素生效：文字沿圆形边缘环绕 */
  }
</style>

<div class="article">
  <img class="avatar" src="avatar.png" alt="作者头像" />
  <p>一段较长的作者介绍……文字会绕着头像的圆形边缘排列，而不是绕着方形的外框。</p>
</div>
```

多栏布局不要再用浮动，直接用 [Flex](/basics/css/05-flex) 或 [Grid](/basics/css/06-grid)。以前用浮动实现的圣杯、双飞翼布局见 [两栏、三栏布局](/basics/css/08-classic-layout)。

## 面试官可能追问

::: details 为什么给 clear 的元素设 margin-top 好像没效果？
被清除的元素会先被推到浮动元素下方，它的 `margin-top` 是相对前面的**普通流**元素计算的，不是相对浮动元素。浮动元素比较高时，这段 margin 被"吃"进了推下来的距离里，看起来就没有生效。想在浮动元素和下面的内容之间留空隙，给浮动元素设 `margin-bottom`，或者给父元素用 `flow-root` 后再设间距。
:::

::: details 用 float 和 inline-block 做横向排列有什么区别？
`inline-block` 元素仍在行内排版，HTML 里标签之间的换行会变成一个空格，元素之间出现缝隙，并且默认按基线对齐，高度不同时会上下错开，见 [line-height 和 vertical-align](/basics/css/20-inline-formatting)。浮动元素之间没有缝隙，但父元素需要清除浮动。两种方式现在都可以用 Flex 代替。
:::

::: details 浮动元素会和 margin 合并吗？
不会。浮动元素的 margin 不和任何元素合并，两个上下排列的浮动元素之间的垂直 margin 也是相加，不像普通流中的块级元素那样合并。
:::

## 易错点

- 浮动元素后面的块级盒子并没有"让位"，让位的是盒子里的文字，所以它的背景会出现在浮动元素下面
- 用 `overflow: hidden` 清除浮动后，阴影、下拉菜单、溢出的提示气泡会被裁掉
- `clear` 写在父元素上不能包含浮动子元素，它只移动设置了 `clear` 的元素自己
- 在 flex 或 grid 容器的子项上写 `float`，不会有任何效果
