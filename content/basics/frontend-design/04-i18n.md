# 前端国际化（i18n）方案怎么设计？语言包、格式化和路由怎么处理？

::: tip 一句话回答
国际化不只是翻译文案，还包括**日期、数字、货币格式**、**复数和语序**、**从右到左（RTL）的语言**和**多语言 SEO**。方案分几块：**语言包**按语言和页面拆分、懒加载、缺失时回退到默认语言；文案用 vue-i18n 这类库的**消息格式**处理插值和复数；格式化统一交给 **Intl**，不手拼字符串；语言按 **URL 前缀 > Cookie > 浏览器语言** 的优先级确定；每种语言有**独立 URL**，服务端渲染出对应语言并输出 **hreflang**。
:::

## 详细解析

### 要解决哪些问题

- **文案**：几千条文案要翻译、更新、追踪缺失
- **格式**：同一个日期，中文是"2026年10月25日"，美式英语是"October 25, 2026"；德语用逗号做小数点
- **复数和语序**：英语区分 1 apple 和 2 apples，俄语有更多形式，中文不变；不同语言的词序不同，不能把几段翻译拼起来
- **RTL**：阿拉伯语、希伯来语从右往左排版，整个布局要镜像
- **SEO**：搜索引擎要能抓到每种语言的页面，并知道它们互为翻译

### 语言包和消息格式

```text
locales/
  zh-CN/common.json  zh-CN/order.json
  en-US/common.json  en-US/order.json
```

- **按语言和页面（模块）拆分**，首屏只加载当前语言的公共包，进入某个页面再加载对应模块
- **回退**：`en-GB` 缺的键先找 `en`，再找默认语言，开发环境打印缺失警告
- **键名**用"模块.语义"，如 `order.submitButton`，不要用中文原文当键，原文一改键就失效
- 语言包放在翻译平台维护，CI 里同步；开发只改默认语言

vue-i18n 用 Composition API 的写法（只示意写法）：

```ts
import { createI18n, useI18n } from 'vue-i18n'

const i18n = createI18n({
  legacy: false, // 用 Composition API；legacy 选项默认仍是 true
  locale: 'zh-CN',
  fallbackLocale: 'en-US',
  messages: {
    'en-US': {
      greeting: 'Hello, {name}', // 命名插值
      apple: 'no apples | one apple | {count} apples', // 复数用 | 分隔
    },
  },
})

// 组件里
const { t, locale } = useI18n()
t('greeting', { name: 'Ann' }) // "Hello, Ann"
t('apple', 0) // "no apples"
t('apple', 3) // "3 apples"，{count} 自动填入
```

vue-i18n 较新的版本已经弃用 Legacy API（计划在下一个大版本移除），`$tc` 已移除，复数直接给 `t` 传数字。

懒加载语言包的做法：用动态 `import()` 加载 `./locales/${locale}.json`，调用 `i18n.global.setLocaleMessage` 注册，再切换 `locale` 并更新 `<html lang>`。一般放在路由的 `beforeEach` 里（见 [路由守卫](/basics/vue/16-router-guards)）。

### 格式化交给 Intl

```js
const d = new Date(Date.UTC(2026, 9, 25, 6, 30))
const opt = { dateStyle: 'long', timeStyle: 'short', timeZone: 'Asia/Shanghai' }
new Intl.DateTimeFormat('zh-CN', opt).format(d) // "2026年10月25日 14:30"
new Intl.DateTimeFormat('de-DE', opt).format(d) // "25. Oktober 2026 um 14:30"

new Intl.NumberFormat('en-US', { style: 'currency', currency: 'EUR' }).format(1234567.891) // "€1,234,567.89"
new Intl.NumberFormat('de-DE', { style: 'currency', currency: 'EUR' }).format(1234567.891) // "1.234.567,89 €"（€ 前是不换行空格 U+00A0）
new Intl.NumberFormat('zh-CN', { notation: 'compact' }).format(12345678) // "1235万"

new Intl.RelativeTimeFormat('zh-CN', { numeric: 'auto' }).format(-1, 'day') // "昨天"
new Intl.ListFormat('zh-CN', { type: 'conjunction' }).format(['苹果', '香蕉', '橙子']) // "苹果、香蕉和橙子"

new Intl.PluralRules('en-US').select(1) // "one"
new Intl.PluralRules('ru').select(5) // "many"
new Intl.PluralRules('zh-CN').select(1) // "other"，中文不区分单复数
```

- 时间在服务端和接口里一律用 UTC 或带时区的 ISO 字符串，显示时再按用户时区格式化
- 货币的币种由业务决定，和界面语言无关：德语界面也可能显示美元
- 构造 `Intl` 对象有开销，同样的参数要缓存实例复用
- 按词切分用 `Intl.Segmenter`，排序用 `Intl.Collator`，不要自己写规则

### 语言从哪来、路由和 SEO

语言的来源和优先级：

1. **URL 前缀**（`/en/about`）：最明确，可分享、可被搜索引擎抓取
2. **Cookie**：用户上次手动选择的语言
3. **浏览器语言**：服务端读 `Accept-Language` 请求头，客户端读 `navigator.languages`
4. 默认语言

只在访问根路径时按 Cookie 和浏览器语言重定向；带了语言前缀的页面不再自动跳转，否则爬虫和分享出去的链接会被跳到别的语言。

每种语言要有**独立的 URL**，服务端渲染直接输出这种语言的 HTML（见 [SSR](/basics/vue/18-ssr-hydration)），并在 `<head>` 里输出 `<link rel="alternate" hreflang="...">` 互相指向、`canonical`、`<html lang>`。

Nuxt 的 @nuxtjs/i18n 模块用 `strategy` 选项控制 URL：

| 策略 | 行为 |
| --- | --- |
| `prefix_except_default` | 默认值，除默认语言外都加语言前缀 |
| `prefix` | 所有语言都加前缀 |
| `prefix_and_default` | 每种语言都有带前缀的 URL，默认语言另有不带前缀的 URL |
| `no_prefix` | URL 不带前缀，靠 Cookie 和浏览器语言检测 |

hreflang、canonical 这些标签由 `useLocaleHead()` 生成，但不会自动注入，要在 `app.vue` 或 layout 里交给 `useHead`；每个 locale 要配置 `language`，并设置 `baseUrl`。

### RTL 和工程化

- **RTL**：在 `<html>` 上设 `dir="rtl"`，CSS 用逻辑属性（`margin-inline-start`、`padding-inline-end`、`text-align: start`）代替 left/right，同一套样式自动镜像；带方向含义的图标（返回箭头）也要翻转
- **提取文案**：脚本扫描代码里的 `t('...')` 调用，和语言包对比，找出未使用和缺失的键
- **CI 检查**：各语言的键集合要和默认语言一致；插值参数名要一致，翻译里把 `{name}` 写成 `{nmae}` 也要拦下来
- **伪本地化**：开发时把文案替换成加长、带特殊字符的版本，提前发现硬编码文案和被截断的布局

## 面试官可能追问

::: details 为什么不能用字符串拼接组装句子？
不同语言语序不同。"共 3 件商品"拼成 `'共' + n + '件商品'`，翻译时只能拆成两段，译者无法调整顺序，复数也没法处理。正确做法是整句作为一条消息，用插值和复数语法表达。
:::

::: details 服务端渲染时，服务端和客户端的格式化结果不一致怎么办？
常见原因是两边时区不同，或者 Node 和浏览器的 ICU 数据不同。格式化时显式传 `timeZone`，用户时区从 Cookie 或用户设置里取；与时间强相关的内容（如"3 分钟前"）可以只在客户端渲染，避免水合不匹配。
:::

::: details 语言包很大，怎么优化加载？
按语言、按页面拆分并懒加载；构建时用 `@intlify/unplugin-vue-i18n` 把消息预编译成消息函数或 AST，运行时不用再编译消息格式；语言包文件名带内容哈希，走 CDN 长缓存。
:::

## 易错点

- 只做了文案翻译，日期、金额还是手拼字符串，换个语言格式就错
- 用浏览器语言做强制跳转，带语言前缀的页面也跳，导致搜索引擎抓不到其他语言
- 复数只区分"1 和其他"，套到俄语、阿拉伯语这类有多种复数形式的语言上出错
- RTL 适配靠写一套 `[dir=rtl]` 覆盖样式，而不是一开始就用逻辑属性
