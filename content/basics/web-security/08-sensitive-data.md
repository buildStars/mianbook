# 前端代码里常见哪些敏感信息泄露？怎么避免？

::: tip 一句话回答
前端的一切最终都会交到用户手里：**构建产物、source map、接口响应、控制台、浏览器存储、URL**，打开开发者工具都能看到。常见的泄露有：把密钥写进前端（构建工具注入的环境变量会原样进入产物）、生产环境公开 source map、接口返回了页面用不到的敏感字段、`console` 打印用户信息、localStorage 里存个人数据、Token 放在 URL 参数里被日志和 Referer 带走。原则是**密钥只放服务端**，调第三方 API 由后端代理；接口**按需返回、在服务端脱敏**；再用 CI 里的**密钥扫描**和上线前的**产物检查**兜底。
:::

## 详细解析

### 常见泄露点

| 位置 | 怎么泄露 | 怎么避免 |
| --- | --- | --- |
| 构建注入的环境变量 | Vite 的 `VITE_` 这类变量在构建时被直接替换进代码，搜索产物就能找到 | 只放接口地址这类公开配置，见[多环境配置](/basics/build/19-env-config) |
| 源码里写死 | 第三方的 secret、测试账号、内部地址直接写在代码或注释里 | 代码评审、提交前做密钥扫描 |
| Source map | 生产环境公开 `.map` 文件，完整源码、注释、内部接口一览无余 | 只上传到错误监控平台，不部署，见 [Source Map](/basics/build/08-source-map) |
| 接口响应 | 列表接口返回了手机号、身份证号、内部状态字段，页面没显示，但网络面板里都看得到 | 后端按场景定义返回字段，敏感字段在服务端脱敏 |
| 控制台和错误监控 | 调试时打印了用户对象、Token，上线没删；监控 SDK 自动采集请求体、URL 和操作记录 | ESLint 的 `no-console` 规则，生产构建移除 `console`；上报前过滤敏感字段 |
| 浏览器存储 | localStorage 里存证件号、地址、聊天记录，退出登录后还在 | 少存，退出时清理，敏感数据不落地 |
| URL 参数 | Token、手机号放在查询参数里 | 放到请求头或请求体里，见下文 |
| 部署目录 | `.env`、`.git` 目录、备份文件被一起传到了静态服务器 | 只部署构建产物目录，Web 服务器禁止访问点开头的文件 |

### 密钥只放服务端

前端要调用需要密钥的第三方 API（大模型、短信、对象存储），一律由自己的后端代理：前端调用自己的接口，后端鉴权、限流之后带上密钥去调用，见[API Key 怎么安全管理](/engineering/security/07-api-key)。对象存储上传这类场景，由后端签发**短期、权限受限**的临时凭证或预签名地址给前端。

要区分"本来就设计成公开的 key"：地图 SDK 的浏览器端 key、错误监控的上报地址、支付的公钥，它们注定会出现在前端，安全靠在服务商控制台里限制可用的域名、设置配额和最小权限，而不是藏起来。

### URL 里的 Token 怎么泄露

- 进入浏览器历史记录，公用电脑上的下一个人能看到
- 被写进 Nginx、CDN、代理的访问日志，日志的访问权限通常比数据库宽松得多
- 统计、监控脚本采集页面地址时一起上报给了第三方
- 用户复制链接分享、截图时带了出去
- 随 `Referer` 请求头发出：默认策略下，跨源请求只带源，但同源请求会带完整地址；页面设置了更宽松的 `Referrer-Policy` 时，完整地址还会发给第三方

必须通过 URL 传递时（如邮件里的重置密码链接），用**一次性、短期有效**的票据，用完立即作废，落地页拿到后马上换成正式凭证，再用 `history.replaceState` 把它从地址栏去掉。

### 在流程里兜底

- **提交前和 CI**：用 gitleaks 这类工具扫描代码和提交历史，并开启代码托管平台的密钥扫描
- **构建之后**：检查产物里有没有 `.map` 文件、密钥格式的字符串、内网地址，有就让流水线失败
- **发现泄露**：先在服务商那里作废、轮换密钥，再清理代码。只从 Git 历史里删掉没用，别人可能已经拿到了

## 代码示例

构建之后扫描产物的简单脚本：

```js
// scripts/check-dist.mjs：构建之后执行，发现问题就让 CI 失败
import { readdir, readFile } from 'node:fs/promises'
import path from 'node:path'

const DIST = process.argv[2] ?? 'dist'
// 规则按项目补充；专门的密钥扫描工具规则更全
const RULES = [
  { name: '私钥', re: /-----BEGIN [A-Z ]*PRIVATE KEY-----/ },
  { name: '疑似密钥', re: /(secret|password|private_?key)["']?\s*[:=]\s*["'][^"']{8,}/i },
  { name: '内网地址', re: /\b(10\.\d+\.\d+\.\d+|192\.168\.\d+\.\d+)\b/ },
]

const problems = []
for (const file of await readdir(DIST, { recursive: true })) {
  if (file.endsWith('.map')) problems.push(`${file}：不应部署 source map`)
  if (!/\.(js|css|html|json)$/.test(file)) continue
  const text = await readFile(path.join(DIST, file), 'utf8')
  for (const { name, re } of RULES) if (re.test(text)) problems.push(`${file}：${name}`)
}

if (problems.length) {
  console.error(problems.join('\n'))
  process.exit(1)
}
console.log('产物检查通过')
```

## 面试官可能追问

::: details 前端代码做混淆、加密，能保护里面的密钥吗？
不能。代码要在用户的浏览器里运行，运行时密钥一定会以明文出现在内存里，用它发出的请求在网络面板里也看得到。混淆只能增加分析的时间，对有经验的人来说只是多花一点工夫。需要保密的东西只能放在服务端。
:::

::: details 接口返回了多余的字段，前端不展示不就行了？
不行。网络面板、抓包工具、直接调用接口都能看到完整的响应，"页面上没显示"不等于用户拿不到。字段要在服务端按场景裁剪，脱敏也要在服务端做：只在前端把手机号显示成 `138****1234`，接口里却是完整号码，等于没脱敏。同理，前端隐藏按钮、路由守卫也不是权限控制，接口必须自己校验权限。
:::

::: details 错误监控、埋点会泄露什么？怎么处理？
监控 SDK 为了方便排查，常常会自动采集页面 URL、请求和响应内容、用户操作记录、控制台日志，里面可能有 Token、手机号、表单内容。处理方法：关闭不需要的自动采集项；在 SDK 提供的上报前钩子里过滤敏感字段；不要把用户的完整信息作为上下文附加到错误上，只带用户 ID。监控方案见[前端监控](/basics/browser/20-monitoring)。
:::

## 易错点

- 以为 `.env` 文件没提交到仓库就安全：带公开前缀的变量照样被打包进产物
- 只在前端做脱敏，接口返回的仍是完整数据
- 密钥泄露后只从代码和 Git 历史里删除，没有在服务商那里作废
- `hidden-source-map` 只是不在产物里写引用注释，`.map` 文件没从部署目录删掉，照样能被直接下载
