# 小程序的分包和启动性能怎么优化？

::: tip 一句话回答
启动慢主要慢在**代码包下载和注入**，所以优化的主线是"让启动时需要的代码尽量少"。**分包**把非首屏页面拆出去，主包只放启动页和公共代码；以微信小程序为例，**主包和单个分包都不能超过 2M**，所有分包总大小另有上限。**独立分包**可以不加载主包直接启动，适合活动页这类独立入口；**分包预下载**在进入某个页面时提前拉取接下来可能用到的分包。代码层面开启**按需注入**和**用时注入**，只注入当前页面用到的组件；数据层面用**数据预拉取**，让首屏数据在启动时就开始请求。
:::

## 详细解析

### 启动流程和耗时来源

```text
冷启动：
  准备运行环境 → 下载代码包（首次或有更新时）→ 注入代码（逻辑层执行 JS）
  → 首页 onLoad、请求数据 → 视图层首次渲染 → 首屏可见
```

下载和注入的耗时都和代码量正相关，数据请求是另一条耗时线。双线程架构下逻辑层和视图层分开运行，渲染数据要跨线程传输，原理见 [小程序双线程架构](/basics/cross-platform/01-miniprogram-arch)。

### 分包

- **主包**：放启动页、TabBar 页和所有分包都要用的公共代码与资源
- **普通分包**：在 app.json 的 `subPackages` 里声明，用户进入分包内页面时才下载。分包可以引用主包的内容；默认不能引用其他分包的内容，要跨分包用组件或 JS，得走**分包异步化**：组件配 `componentPlaceholder` 占位，JS 用 `require.async`
- **独立分包**：声明 `independent: true`，从它的页面启动时不下载主包，打开更快。代价是不能依赖主包和其他分包里的代码、组件和样式（`app.wxss` 也不生效；只有通过分包异步化引用的 JS、组件、插件例外），`getApp()` 在主包未加载时拿到的也不是完整的 App 实例，公共逻辑要自己复制一份或做兼容
- **分包预下载**：在 app.json 的 `preloadRule` 里配置"进入某页面时预下载哪些分包"，可以用 `network` 限定只在 Wi-Fi 下预下载

拆分原则：首屏和高频页面留在主包；低频或独立的业务（设置、帮助、活动页）拆成分包；只被某个分包使用的第三方库和图片放进那个分包，不要堆在主包。体积限制的具体数字各平台不同、也会调整，以官方文档为准。

### 按需注入和用时注入

默认情况下，启动时会注入主包里所有页面和自定义组件的代码，哪怕首页只用了几个。

- **按需注入**：在 app.json 配置 `"lazyCodeLoading": "requiredComponents"`，启动时只注入当前页面需要的组件代码
- **用时注入**：在按需注入的基础上，给组件配置 `componentPlaceholder`，组件真正渲染时才注入，之前用占位组件代替。适合首屏之外才出现的复杂组件

### 数据和渲染

- **数据预拉取**：在小程序后台配置后，微信会在小程序冷启动时提前请求开发者服务器，页面里用 `wx.getBackgroundFetchData` 取结果，首屏请求和代码注入并行
- **缓存兜底**：首屏先用本地缓存的上次数据渲染，再请求新数据刷新
- **首屏轻量化**：首屏 setData 的数据要少，长列表分页，图片懒加载。setData 本身的优化见 [setData 为什么会卡](/basics/cross-platform/02-setdata)
- **减少启动同步逻辑**：`App.onLaunch` 里不要做同步的重计算或多余的同步存储读取，非必要的初始化延后执行

## 面试官可能追问

::: details 独立分包里怎么用到主包的公共代码？
不能直接引用，只能复制一份进独立分包，或者抽成 npm 包分别打进去。全局状态也要小心：从独立分包启动时主包还没加载，App 里定义的全局数据不存在；后来用户跳到主包页面，主包加载后才有完整的 App 实例。所以独立分包里通常用 `getApp({ allowDefault: true })` 拿一个默认实例（App 还没注册时返回空对象），主包加载、App 注册后，默认实例上设置的属性会合并进真正的 App，并覆盖同名属性。
:::

::: details 怎么定位启动慢慢在哪？
开发者工具和真机调试里有性能面板，可以看到下载、注入、首次渲染各阶段的耗时；代码依赖分析能看出主包里哪些文件最大、哪些文件没被引用。线上可以用小程序后台的性能监控看真实用户的启动耗时分布。先看是包太大（下载和注入慢），还是首屏请求慢，再对症处理。
:::

::: details 分包会影响页面之间的跳转吗？
跳到还没下载的分包页面时，要先下载分包，会有一次等待，网络差时比较明显。这就是分包预下载的用途：在用户大概率要去的页面之前预先下载。预下载本身也占带宽，只配置真正高频的路径。
:::

## 易错点

- 把分包当成"主包超限的补救"，只在超限时才拆；实际上主包越小启动越快，应该主动拆
- 公共组件放在某个分包里，被另一个分包直接引用：没配 `componentPlaceholder` 走分包异步化时会报错；配了也要接受首次渲染先显示占位、等对方分包下载完的代价，真正公共的组件还是放主包
- 独立分包依赖了主包的代码或 App 全局数据，单独启动时出错
- 只拆包不开按需注入，主包里所有组件仍在启动时全部注入
