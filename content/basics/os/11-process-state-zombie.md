# 进程有哪些状态？什么是僵尸进程和孤儿进程？

::: tip 一句话回答
经典的五态模型是**新建、就绪、运行、阻塞、终止**。Linux 里 `ps` 看到的是 **R**（运行或可运行）、**S**（可中断睡眠）、**D**（不可中断睡眠）、**Z**（僵尸）、**T**（停止）。**僵尸进程**是子进程已经退出、但父进程还没调用 `wait` 回收，进程表项一直留着；**孤儿进程**是父进程先退出，子进程被 **init（PID 1）收养**，由它负责回收。
:::

## 详细解析

### 五态模型

```text
         调度选中
  就绪 ─────────► 运行 ───► 终止
   ▲   ◄─────────  │
   │   时间片用完   │ 等待 I/O、锁等
   │               ▼
   └──── 事件完成 ── 阻塞
```

- **就绪**：万事俱备，只差 CPU
- **运行**：正在 CPU 上执行
- **阻塞**：在等某个事件（磁盘读完、网络数据到达），给它 CPU 也没用

阻塞不能直接变运行，要先回到就绪队列等调度。状态切换带来的开销见 [上下文切换](/basics/os/08-context-switch)。

### Linux 里的状态

| 状态 | 含义 | 说明 |
| --- | --- | --- |
| R | 运行或可运行 | Linux 不区分"运行"和"就绪"，都在运行队列里 |
| S | 可中断睡眠 | 等待事件，能被信号唤醒。大多数空闲进程都是 S |
| D | 不可中断睡眠 | 一般在等磁盘或 NFS 这类 I/O，信号打不断，`kill -9` 也杀不掉 |
| Z | 僵尸 | 已退出，等父进程回收 |
| T | 停止 | 收到 `SIGSTOP` 或 `Ctrl+Z`，或被调试器暂停 |

大量 D 状态进程通常意味着存储出了问题，它们还会推高 load average，排查方法见 [线上服务器 CPU 或内存飙高怎么排查](/basics/os/09-linux-troubleshoot)。

### 僵尸进程

子进程调用 `exit` 后，内存、文件描述符等资源都释放了，但内核还保留着它的进程表项（PID、退出码、资源统计），等父进程用 `wait` 或 `waitpid` 来读。读走之前，它就是僵尸。

- 危害：僵尸本身不占 CPU 和内存，但**占着 PID**。数量很多时会耗尽 PID，新进程创建失败
- 原因：父进程没处理子进程退出，常见于自己 fork 子进程却不回收的程序
- 处理：`kill` 僵尸进程没用，它已经死了。要让父进程回收，或者杀掉父进程，僵尸变成孤儿后被 init 收养并回收

父进程的正确写法：注册 `SIGCHLD` 信号处理，在里面循环调用 `waitpid(-1, &status, WNOHANG)`，直到没有已退出的子进程。用循环是因为多个子进程同时退出时，信号可能合并成一次。

### 孤儿进程

父进程先退出，子进程还在跑，就成了孤儿。内核把它的父进程改成 init（或者设置了 subreaper 的祖先进程）。init 会持续回收子进程，所以孤儿进程本身无害。守护进程就是故意利用这一点：fork 后父进程退出，子进程脱离终端在后台运行。

### 容器里的 PID 1 问题

容器有自己的 PID 命名空间，启动命令就是 PID 1。如果它是普通业务进程，不会回收被收养的孤儿，僵尸就会在容器里堆积。另外内核对 PID 1 有特殊保护：它没注册处理函数的信号会被忽略，`docker stop` 发的 `SIGTERM` 可能没反应，等超时后被强杀。解决办法是用 `tini` 这类轻量 init 当 PID 1（`docker run --init`），也可以参考 [Dockerfile 里 PID 1 和信号转发的讨论](/basics/container/03-multi-stage)。

## 代码示例

```bash
# STAT 列第一个字母是状态；找僵尸进程和它的父进程
ps -eo pid,ppid,stat,cmd | awk '$3 ~ /^Z/'

# 找 D 状态进程，WCHAN 列显示它卡在哪个内核函数
ps -eo pid,stat,wchan:32,cmd | awk '$2 ~ /^D/'

# 看进程树，确认父子关系
pstree -p <父进程PID>
```

## 面试官可能追问

::: details 为什么要设计僵尸状态，子进程退出直接全部清掉不行吗？
父进程需要知道子进程的退出码和资源使用情况，比如 shell 要拿 `$?`。如果子进程一退出就全清掉，父进程之后调用 `wait` 就什么都拿不到了。僵尸就是保留这点信息的最小代价。
:::

::: details 父进程不想关心子进程的退出状态，怎么避免僵尸？
可以把 `SIGCHLD` 的处理方式设为 `SIG_IGN`，Linux 下子进程退出后会被内核自动回收。另一种办法是两次 fork：子进程再 fork 一个孙进程后立刻退出，父进程回收子进程，孙进程变成孤儿交给 init。
:::

::: details D 状态的进程为什么杀不掉？
它在内核里等待一个不能被打断的操作，比如等磁盘返回数据，中途响应信号可能让内核数据处于不一致状态。只能等 I/O 完成或存储恢复。如果是 NFS 挂载卡住，往往要先处理挂载问题。
:::

## 易错点

- 僵尸进程不能用 `kill -9` 清理，要处理它的父进程
- Linux 的 R 包含"正在运行"和"就绪等待 CPU"两种情况
- 孤儿进程无害，会被 init 收养回收；有害的是没人回收的僵尸
- S 和 D 都是睡眠，区别在于能不能被信号唤醒
