# 内存分页和分段有什么区别？什么是内部碎片和外部碎片？

::: tip 一句话回答
**分段**按程序的逻辑结构划分内存（代码段、数据段、栈），每段长度不固定；**分页**把内存切成**固定大小的页**（常见 4KB），和程序逻辑无关。分段的问题是**外部碎片**：空闲内存总量够，但被切成不连续的小块，放不下大段。分页消除了外部碎片，代价是**内部碎片**：最后一页用不满也要整页分配。**段页式**先分段再在段内分页。Linux 在 x86-64 上基本只用分页，段机制只保留最低限度。
:::

## 详细解析

### 分段

程序天然由几块组成：代码、全局数据、堆、栈。分段就按这个划分，每段有一个基地址和长度，逻辑地址写成"段号 + 段内偏移"：

```text
逻辑地址 (段号 2, 偏移 100)
  └► 查段表：段 2 → 基址 0x8000，长度 0x400
       偏移 100 < 长度，合法
  └► 物理地址 = 0x8000 + 100
```

优点是贴合程序结构，可以按段设置权限（代码段只读可执行，数据段可读写），也方便共享整个代码段。缺点是每段要占一块**连续的**物理内存，段的大小各不相同。

### 分页

把虚拟地址空间和物理内存都切成同样大小的块，虚拟的叫**页**，物理的叫**页框**。页表记录"虚拟页号 → 物理页框号"，任意一页可以放到任意一个空闲页框里，不要求连续：

```text
虚拟地址 = 虚拟页号 | 页内偏移
  └► 查页表：虚拟页号 → 物理页框号
  └► 物理地址 = 物理页框号 | 页内偏移
```

页表结构、缺页中断和页面置换属于虚拟内存的内容，见 [虚拟内存是什么](/basics/os/03-virtual-memory)，这里不展开。

### 两种碎片

| 碎片 | 位置 | 怎么产生 | 典型来源 |
| --- | --- | --- | --- |
| 外部碎片 | 已分配区域**之间** | 大小不一的块反复分配、释放，留下一堆不连续的小空洞 | 分段、可变分区分配 |
| 内部碎片 | 已分配区域**内部** | 按固定单位分配，实际需求小于分配单位，多出的部分浪费 | 分页、固定大小的内存池 |

举个假设的例子：页大小 4KB，进程需要 10KB，要分 3 页共 12KB，最后一页有 2KB 用不上，这就是内部碎片。平均下来每个内存区域浪费半页左右。

外部碎片可以靠**紧凑**（移动已分配的段，把空洞挤到一起）缓解，但移动内存成本高，还要更新所有地址。分页从根本上避免了这个问题，因为任何空闲页框都能用。

### 段页式和 Linux 的做法

段页式先按逻辑分段，每个段内部再分页。地址转换要查两次：先查段表找到该段的页表，再查页表找到页框。它兼顾了分段的逻辑保护和分页的内存利用率，代价是转换更复杂。

x86 硬件一直要求地址先经过分段。Linux 的做法是把主要的段基址设为 0、长度覆盖整个地址空间（平坦模型），分段相当于直通，保护和映射全靠分页。到了 x86-64 的 64 位模式，硬件本身基本不再对代码段和数据段做基址和长度检查，只有 FS、GS 等少数段寄存器还有特殊用途（例如线程局部存储）。进程地址空间里的"代码段、堆、栈"是 Linux 按虚拟内存区域管理的逻辑概念，不是硬件分段。

## 面试官可能追问

::: details 页越大越好还是越小越好？
页越大，页表越小，TLB 能覆盖的内存越多，命中率更高；但内部碎片更大，按页换入换出的粒度也更粗。数据库、JVM 这类大内存应用常开启大页（例如 2MB）减少 TLB 未命中。
:::

::: details 用户程序里 malloc 产生的碎片属于哪种？
堆内存由 `malloc` 的分配器在用户态管理，反复分配、释放不同大小的块会在堆里留下空洞，属于外部碎片；分配器按对齐或按尺寸档位分配多出来的部分是内部碎片。它和操作系统分页是两层东西：分配器向内核要的是整页，内部再切小块。
:::

::: details 分页之后还有外部碎片吗？
在页框分配层面没有，因为每页大小相同、可以放在任何位置。但内核有时需要**物理连续**的多个页框（例如某些设备的 DMA 缓冲、大页），Linux 用伙伴系统管理页框，长时间运行后仍会出现"空闲页够、连续的大块不够"的情况。
:::

## 易错点

- 分页产生的是内部碎片，分段产生的是外部碎片，不要说反
- 进程地址空间里的"代码段、数据段"是逻辑划分，不代表 Linux 在用硬件分段
- 分页不要求物理内存连续，但同一页内部的 4KB 是连续的
- 段页式的段表查到的是该段的页表，不是直接得到物理地址
