# 大模型的能力怎么衡量？MMLU、HumanEval 这类基准测的是什么，有什么局限？

::: tip 一句话回答
公开基准用**固定题目 + 自动打分**衡量模型某方面的能力：MMLU 类是覆盖很多学科的**多选题**，测知识和推理；HumanEval 类给函数说明让模型写代码，用单元测试判断对错，指标是 **pass@k**；数学类测多步推理；Arena 类让真人对两个匿名模型的回答**两两投票**，算出排名。它们的局限是**数据污染**、**针对性刷榜**和**与真实业务脱节**，所以选型和上线前还要用自己的业务数据建评测集。
:::

## 详细解析

### 常见基准分别测什么

| 类型 | 例子 | 怎么打分 | 主要测什么 |
| --- | --- | --- | --- |
| 知识与推理多选 | MMLU 一类，几十个学科的选择题 | 选项是否正确，算准确率 | 知识广度、基本推理 |
| 代码生成 | HumanEval 一类，给函数签名和说明 | 跑单元测试，算 pass@k | 写出能跑通的代码 |
| 数学推理 | 小学应用题、竞赛题一类 | 比对最终答案 | 多步推理 |
| 对话偏好 | Arena 一类，匿名两两对比 | 真人投票，用统计模型算排名 | 综合体验、用户偏好 |
| 长上下文、工具调用、Agent | 大海捞针、多步任务一类 | 任务是否完成 | 特定能力 |

### pass@k

对每道题生成 n 个答案（n ≥ k），其中 c 个通过测试。pass@k 估计的是"随机抽 k 个，至少有一个通过"的概率：

```text
pass@k = 1 - C(n - c, k) / C(n, k)
```

k = 1 时就是 c / n。不直接只生成 k 个算通过率，是因为样本少时方差很大，多采样再用这个公式估计更稳定。

```js
function passAtK(n, c, k) {
  if (n - c < k) return 1
  // 1 - C(n-c, k) / C(n, k)，用连乘避免组合数溢出
  let fail = 1
  for (let i = n - c + 1; i <= n; i++) fail *= 1 - k / i
  return 1 - fail
}

console.log(passAtK(20, 3, 1).toFixed(3)) // 0.150
console.log(passAtK(20, 3, 5).toFixed(3)) // 0.601
```

### 局限

1. **数据污染**：基准题目公开在网上，可能被爬进训练数据。模型可能是"背过答案"而不是会做，表现为改写题目后分数明显下降
2. **刷榜**：针对某个基准调提示词、调答题格式、挑选有利的评测设置，分数上去了，能力未必提高。不同报告的评测设置（few-shot 数量、是否用思维链）不同，分数不能直接比
3. **饱和**：头部模型分数都接近上限后，基准失去区分度，只能换更难的
4. **和业务脱节**：多选题考不出"按公司格式回复客服工单"；函数级单元测试测不出在大仓库里改代码的能力
5. **偏好投票的偏差**：真人倾向于更长、格式更漂亮、语气更自信的回答，不等于更正确

### 业务上怎么做

公开基准适合粗筛，确定"这几个模型值得试"。真正选型要用自己的数据：从线上真实请求里抽样，标注期望结果，覆盖难例和边界情况（见 [评测集怎么建](/engineering/eval/03-eval-dataset)）。打分可以用规则、人工或 [LLM 当裁判](/engineering/eval/02-llm-as-judge)。自建评测集也要防止被反复调优刷到过拟合（见 [评测集过拟合](/engineering/eval/12-eval-overfitting)）。

## 面试官可能追问

::: details 怎么判断一个模型有没有被数据污染？
可以把题目改写、换数字、换选项顺序后重测，分数大幅下降就可疑；也可以检测模型能否逐字补全题目原文。更根本的办法是用训练数据截止之后才出的新题，或者不公开的私有评测集。
:::

::: details Arena 类排名用的是什么方法？
收集大量"A 和 B 谁更好"的两两投票，用 Elo 或 Bradley-Terry 一类的统计模型估计每个模型的相对强度，再给出置信区间。它反映的是用户整体偏好，不代表在某个具体任务上的能力。
:::

::: details 推理模型的评测有什么特别要注意的？
推理模型的分数受"思考预算"影响很大，允许生成的 token 越多分数往往越高，比较时要说明预算和成本。还常用多次采样投票，要区分单次结果和投票结果（见 [推理模型](/ai/llm/10-reasoning-models)）。
:::

## 易错点

- 把不同评测设置下的分数直接对比：few-shot 数量、提示词、是否用思维链都会影响结果
- pass@k 不是"生成 k 次的通过率"，而是用 n 次采样估计的概率
- 公开基准分数高不代表业务效果好，上线前一定要用业务数据评测
