# 什么是 Scaling Law？大模型的"涌现能力"指什么？

::: tip 一句话回答
Scaling Law 是一组经验规律：模型的**测试损失**随**参数量**、**训练数据量**和**训练计算量**的增加，按**幂律**稳定下降，在对数坐标上近似一条直线。后来的研究发现，计算预算固定时，参数量和数据量应该**同比例增长**，之前很多模型参数太多、数据太少。**涌现能力**指某些能力在小模型上几乎没有，规模过了某个点后突然出现；但也有研究认为这种"突然"很大程度是评测指标造成的错觉。
:::

## 详细解析

### 幂律关系

以损失 L 为纵轴、规模为横轴，在其他因素不成为瓶颈时：

```text
L(N) ≈ (N_c / N)^α      N：参数量
L(D) ≈ (D_c / D)^β      D：训练 token 数
L(C) ≈ (C_c / C)^γ      C：训练计算量，对稠密 Transformer 约为 6 × N × D
```

α、β、γ、N_c 等都是拟合出来的常数。含义是：规模每扩大 10 倍，损失按固定比例下降，回报递减但稳定可预测。

这个规律的价值在于**可预测**：先用一系列小模型拟合曲线，就能在花大钱训练大模型之前估计它的损失，决定预算怎么分。

### 计算最优：参数和数据怎么分

计算量 C 固定时，可以训大模型、少数据，也可以训小模型、多数据。早期研究倾向于把预算更多给参数。后来以 Chinchilla 为代表的研究重新做实验，结论是：

- 计算最优时，参数量和训练 token 数应该**大致同比例**扩大
- 按这个比例，当时不少大模型是"训练不足"的：同样的算力训一个更小的模型、喂更多数据，效果更好
- 常被引用的经验比例是每个参数配 20 个左右的 token，这是那项研究的拟合结果，不是定律

实践中模型往往训得比"计算最优"更久：推理成本由参数量决定，小一点的模型多训些数据，训练多花点钱，部署时每次调用都省钱。

### 涌现能力

涌现能力指：某个任务的表现在小模型上接近随机，规模增大到某个范围后**突然**大幅提升，没法从小模型的趋势外推出来。常被举的例子有多位数算术、多步推理、少样本完成某些任务。

争议在于"突然"是不是真的，代表性的质疑来自 *Are Emergent Abilities of Large Language Models a Mirage?* 这篇研究：

- 很多例子用的是**不连续指标**，比如精确匹配：答案全对才得分，错一位就是 0。模型每个 token 的正确率其实在平滑提升，但要求所有 token 都对，整体得分看起来就像突然跳起来
- 换成连续指标（如 token 级准确率、正确答案的概率），很多曲线变得平滑可预测
- 也有些任务换了指标仍然有明显拐点，争论还没有定论

比较稳妥的说法：**损失是平滑下降的，部分下游能力看起来是跳变的，这既和任务性质有关，也和怎么度量有关**。

### 推理时扩展

上面讲的都是训练阶段的扩展。另一个方向是**推理时多花计算**：让模型生成更长的思维链、多次采样投票、搜索并验证。研究发现在一些推理任务上，推理计算量增加时效果也随之提升，能和训练规模互相替代一部分（见 [推理模型](/ai/llm/10-reasoning-models)）。

## 面试官可能追问

::: details Scaling Law 会一直成立吗？
它是经验规律，只在被验证过的范围内可信。现实的限制有：高质量数据可能先用完；损失降低不一定带来下游能力同比例提升；成本增长很快。所以除了堆规模，还有提高数据质量、合成数据、推理时扩展、[MoE](/ai/llm/11-moe) 这类架构改进等方向。
:::

::: details 6ND 这个计算量估计是怎么来的？
前向时每个参数对每个 token 大约做一次乘法和一次加法，约 2 次浮点运算；反向传播大约是前向的两倍。合起来每个参数每个 token 约 6 次，再乘以参数量 N 和 token 数 D。这是忽略注意力等项的粗略估计。
:::

::: details 涌现能力对工程实践有什么影响？
不能只拿小模型的效果判断某个任务"做不了"，也不能假设规模大了就一定能做。选型时要在目标任务上直接评测，同时注意指标的选择会影响你看到的趋势。
:::

## 易错点

- Scaling Law 描述的是**损失**的变化，不是直接描述某个下游任务的准确率
- "每参数 20 个 token"是特定实验的拟合结论，不是必须遵守的规则，实践中常训得更多
- 涌现能力是否"真的突然出现"有争议，不要当成确定的结论
