# MoE（混合专家模型）是什么？为什么参数多了推理却不一定变慢？

::: tip 一句话回答
MoE 把 Transformer 里的 FFN 层换成**多个并列的"专家"FFN**，再加一个**路由器**，每个 token 只送给打分最高的 **top-k 个专家**计算。所以模型的**总参数**很大，但每个 token 实际用到的**激活参数**只占一小部分，计算量接近一个小得多的稠密模型。代价是所有专家都要放进显存，还要处理**负载不均**和多卡之间的**通信**。
:::

## 详细解析

### 结构：只替换 FFN

注意力层保持不变，变化在 FFN（见 [Transformer 的核心结构](/ai/llm/02-transformer)）：

```text
稠密模型：   token → 注意力 → FFN → 下一层

MoE 模型：   token → 注意力 → 路由器 ─┬→ 专家 1 ─┐
                               (打分) ├→ 专家 2 ─┼→ 按权重加权求和 → 下一层
                                      ├→ ...     │
                                      └→ 专家 N ─┘
                               只有 top-k 个专家真正参与计算
```

1. 路由器通常是一个线性层，对每个 token 给 N 个专家打分，经过 softmax 得到权重
2. 选出分数最高的 k 个专家（k 常取 1 或 2），其余专家不计算
3. 把这 k 个专家的输出按权重加权相加，作为这一层的输出

路由是**按 token、按层**做的：同一句话里不同的 token、同一个 token 在不同层，都可能去不同的专家。

### 总参数和激活参数

| 指标 | 含义 | 影响什么 |
| --- | --- | --- |
| 总参数 | 所有专家加起来的参数量 | 显存占用、模型的知识容量 |
| 激活参数 | 每个 token 实际参与计算的参数量 | 每个 token 的计算量、训练成本 |

MoE 的思路是"容量和计算解耦"：用更多参数存知识，但每次只调动其中一部分。在相同的训练计算预算下，MoE 往往能比同等激活参数的稠密模型效果更好。

"推理不一定变慢"要加限定：计算量小了，但**显存要装下全部参数**，部署门槛按总参数算；小批量推理时速度常受限于读取权重的带宽，激活的专家越分散，要读的权重越多。

### 训练难点：负载均衡

路由器是和模型一起学出来的，容易出现"马太效应"：少数专家一开始表现好，分到的 token 越来越多，其他专家得不到训练。常见处理：

- **辅助负载均衡损失**：在总损失里加一项，惩罚各专家分到的 token 比例不均匀
- **专家容量**：给每个专家设处理上限，超出的 token 被丢弃（走残差直连）或者分给下一个候选专家
- **路由加噪声或偏置调整**：训练时让路由别过早固定

### 推理部署：专家并行

专家多时一张卡放不下，通常把不同专家放到不同的卡上（专家并行）。每层都要把 token 发到对应专家所在的卡，算完再收回来，这是两次 all-to-all 通信。批量越大、专家分布越均匀，硬件利用率越高；所以 MoE 更适合大规模在线服务，而不是单卡本地跑。

### 常见的改进

- **细粒度专家**：把专家切得更小、数量更多，k 也相应变大，组合更灵活
- **共享专家**：保留一两个每个 token 都会经过的专家，存放通用知识，其他路由专家专注于细分模式

## 面试官可能追问

::: details 专家真的会按"数学专家""代码专家"这样分工吗？
不完全是。研究观察到的分工多数是 token 层面的模式，比如某类标点、某种语法结构、某个语种的词，很难对应到人能理解的"学科"。"专家"只是一个名字，不要按字面理解成每个专家精通一个领域。
:::

::: details MoE 和多个模型做集成（Ensemble）有什么区别？
集成是每个模型都完整地跑一遍再合并结果，计算量随模型数线性增加。MoE 是一个模型内部的稀疏结构，路由在每层对每个 token 做选择，每次只算 k 个专家，而且专家和路由器是一起端到端训练的。
:::

::: details 对微调和量化有什么影响？
MoE 微调更容易不稳定，路由可能在小数据集上被带偏，常见做法是冻结路由器或保留负载均衡损失。量化能明显降低显存，因为显存瓶颈正好在总参数上。用 LoRA 时，要决定适配器加在注意力层、共享专家还是所有专家上。
:::

::: details 为什么小批量、本地部署时 MoE 的优势不明显？
本地推理一次只处理少量 token，速度主要取决于从显存读多少权重。MoE 需要的显存按总参数算，设备很可能装不下；能装下时，连续生成的 token 会命中不同的专家，读取的权重总量也不少。它的优势在大批量服务时才能充分发挥。
:::

## 易错点

- 把激活参数当成模型大小来估算显存，实际上部署要装下全部参数
- 以为 MoE 是在整句话或整个请求层面选专家，实际是每层对每个 token 单独路由
- 只说"计算量小所以快"，忽略了显存带宽、通信和负载不均对实际速度的影响
