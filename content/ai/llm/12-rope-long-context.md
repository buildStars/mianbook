# RoPE 是怎么编码位置的？模型怎么扩展到更长的上下文？

::: tip 一句话回答
RoPE（旋转位置编码）把 Q 和 K 的维度两两分组，每组按 **"位置 × 该组频率"** 的角度旋转。两个向量都旋转后再做点积，结果只和**两者的位置差**有关，所以模型天然学到的是**相对位置**。直接用到比训练时更长的文本会失效，因为低频维度会转到训练中没见过的角度。扩展的办法主要是**位置插值**、**调大 base（NTK 类方法、YaRN）**，再配合**长文本继续训练**。
:::

## 详细解析

### 为什么需要位置编码

自注意力本身不区分顺序：把输入的 token 打乱，每个 token 得到的注意力结果不变（只是跟着换了位置）。所以要额外注入位置信息，见 [Transformer 的核心结构](/ai/llm/02-transformer)。早期做法是把位置向量加到输入上（绝对位置编码）；RoPE 改成在计算注意力之前，直接对 Q、K 做旋转。

### RoPE 的做法

设向量维度是 d，把它分成 d/2 组，每组两维看成平面上的一个点：

1. 第 i 组的频率是 θ_i = base^(-2i/d)，base 原始取 10000。i 越小频率越高，转得越快
2. 位置为 m 的 token，第 i 组旋转 m × θ_i 弧度
3. Q 和 K 都这样旋转，V 不旋转

关键性质：位置 m 的 q 和位置 n 的 k 旋转后做点积，结果只取决于 m − n。旋转角度相减，绝对位置被消掉了。

```ts
// 对向量 x 应用位置 pos 的 RoPE：每两维一组，按各自的频率旋转
function rope(x: number[], pos: number, base = 10000): number[] {
  const d = x.length
  const out = new Array<number>(d)
  for (let i = 0; i < d / 2; i++) {
    const theta = pos * base ** (-(2 * i) / d) // 维度越靠后，频率越低
    const [a, b] = [x[2 * i], x[2 * i + 1]]
    out[2 * i] = a * Math.cos(theta) - b * Math.sin(theta)
    out[2 * i + 1] = a * Math.sin(theta) + b * Math.cos(theta)
  }
  return out
}

const dot = (u: number[], v: number[]) => u.reduce((s, ui, i) => s + ui * v[i], 0)
const q = [0.3, -1.2, 0.8, 0.5, -0.4, 1.1, 0.9, -0.7]
const k = [1.0, 0.2, -0.6, 0.4, 0.7, -0.3, 0.1, 0.5]

// 位置 (5, 2) 和 (105, 102) 的距离都是 3，点积相同
console.log(dot(rope(q, 5), rope(k, 2)).toFixed(6)) // -0.853521
console.log(dot(rope(q, 105), rope(k, 102)).toFixed(6)) // -0.853521
```

多种频率并存，像钟表的秒针、分针、时针：高频组区分相邻的 token，低频组表达远距离的位置关系。

### 为什么超出训练长度就失效

假设训练长度是 4K。高频组在 4K 内已经转了很多圈，所有角度都见过；低频组在 4K 内可能还没转完一圈，位置到 8K 时出现的角度是训练中从没见过的。模型对这些角度没有学过，注意力分布会乱掉，表现为困惑度陡增、输出重复或胡言乱语。

### 扩展上下文的几种方法

| 方法 | 思路 | 特点 |
| --- | --- | --- |
| 位置插值（PI） | 把位置按比例缩小，比如 8K 的位置乘 0.5，映射回 0～4K | 简单，角度都在见过的范围里；但高频组被压缩，相邻 token 更难区分，需要少量微调 |
| 调大 base（NTK-aware 等） | 增大 base，让低频组转得更慢，高频组基本不受影响 | 不微调也有一定效果，微调后更好 |
| YaRN | 按频率分段处理：高频不动、低频插值、中间过渡，再给注意力加温度修正 | 兼顾近距离分辨率和远距离外推，被很多长上下文模型采用 |
| 长文本继续训练 | 用长文档继续训练一段时间，常和上面的方法组合 | 效果最可靠，但需要长文本数据和算力 |

另一类思路是不用旋转，比如 **ALiBi** 直接在注意力分数上按距离减去一个线性惩罚，外推更平滑。

### 能装下不等于能用好

位置编码只解决"长度上不崩"。模型能不能在长文本里找到并用好信息，还取决于训练数据里有没有足够多的长依赖样本。实际表现常见中间部分被忽略的问题，见 [上下文窗口](/ai/llm/04-context-window)；长度增加带来的显存压力见 [KV Cache](/ai/llm/08-kv-cache)。

## 面试官可能追问

::: details RoPE 为什么只旋转 Q 和 K，不旋转 V？
位置信息只需要影响"谁关注谁"，也就是注意力分数，而分数是 Q 和 K 的点积。V 是被加权汇总的内容，旋转它会让输出带上和位置相关的扭曲，没有好处。
:::

::: details RoPE 有"远程衰减"是什么意思？
在一定假设下，随着两个 token 距离增大，旋转后点积的上界整体呈下降趋势，模型自然倾向于更关注近处。这是一个统计意义上的趋势，不是硬性规定，模型仍然可以学会关注很远的 token。
:::

::: details 为什么不直接在超长文本上从头训练？
注意力的计算量随长度平方增长，长文档在语料里也少，从头就用超长序列训练很不划算。常见做法是先用较短的长度完成大部分预训练，最后阶段再扩展位置编码，用长文本继续训练。
:::

## 易错点

- 把 RoPE 说成加到输入 embedding 上的位置向量，它是在每层注意力里旋转 Q 和 K
- 以为位置插值"不需要任何训练"，多数方法微调一下效果明显更好
- 认为窗口扩展到多长，模型就能在这个长度上同样好地利用信息
