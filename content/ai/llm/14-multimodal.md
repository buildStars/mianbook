# 多模态大模型是怎么"看懂"图片的？

::: tip 一句话回答
常见做法是把图片也变成"token"。**视觉编码器**（通常是 ViT）把图片切成小块（patch），每块编码成一个向量；**投影层**把这些向量映射到语言模型的 embedding 空间；然后和文本 token 拼在一起送进 **LLM**，由它统一做注意力和生成。训练一般分两步：先用图文对**对齐**视觉特征和文本空间，再用图文指令数据做**指令微调**。图片会占用大量 token，高分辨率和细小文字是成本和效果的主要矛盾。
:::

## 详细解析

### 整体结构

```text
图片 ──→ 视觉编码器（ViT）──→ patch 向量 ──→ 投影层 ──→ 图像 token ─┐
                                                                    ├──→ LLM ──→ 文本输出
文本 ──→ 分词 ──→ 文本 token embedding ─────────────────────────────┘
```

1. **切块**：把图片缩放到固定尺寸，切成网格状的 patch，比如每块 14×14 或 16×16 像素
2. **视觉编码**：ViT 对 patch 序列做自注意力，每个 patch 的向量融合了整张图的上下文。编码器常来自 CLIP 这类用图文对比学习训练的模型，它输出的特征本来就和文本语义接近
3. **投影**：用 MLP 等小网络把视觉向量的维度和分布转换成 LLM 能接收的形式；也有方案用一组可学习的查询向量把很多 patch 压缩成固定数量的 token
4. **融合**：图像 token 插在文本里对应的位置，LLM 把它们当作特殊的"词"处理

LLM 本身不认识像素，它读到的是一串已经被翻译到"语言空间"的向量。

### 训练分几步

| 阶段 | 数据 | 训练哪些部分 | 目的 |
| --- | --- | --- | --- |
| 对齐预训练 | 大量图片和描述文字配对 | 常常只训练投影层，编码器和 LLM 冻结 | 让图像 token 落到 LLM 能理解的位置 |
| 指令微调 | 图片问答、图表理解、多轮对话等 | 投影层和 LLM（有时也解冻编码器） | 学会按指令回答关于图片的问题 |

后面还可以接偏好对齐，见 [训练阶段](/ai/llm/06-training-stages)。

另一种路线是**原生多模态**：从预训练开始就把图像和文本混在一起训练，而不是在训练好的 LLM 上外挂视觉模块。两种路线的接口看起来一样，区别在训练方式。

### 分辨率和 token 成本

一张图会变成几百到上千个 token，具体数量取决于模型和分辨率。直接提高输入尺寸，token 数会随边长平方增长。常见的处理：

- **切片**：把大图切成几块分别编码，再加一张缩略图提供全局信息
- **动态分辨率**：按原图长宽比和大小决定 token 数，不强行缩放成正方形
- **token 压缩**：合并相邻的 patch，减少送进 LLM 的数量

调用 API 时，图片通常按 token 计费，可以选择低精度模式省钱。看截图里的小字时要高精度，判断图片大致内容时低精度就够。

### 常见弱点

- **细小文字和密集表格**：分辨率不够时细节在切块和缩放中丢失，结果会编造
- **计数和精确空间关系**：数清楚几个物体、判断谁在谁左边，比描述整体内容难得多
- **图像里的幻觉**：根据常识"脑补"不存在的物体，问题措辞有诱导时更明显，见 [幻觉](/ai/llm/05-hallucination)
- **图片里的文字指令**：图片中嵌入的文字也会被模型读到，可能被用来做提示注入，处理用户上传的图片时要当作不可信输入

## 面试官可能追问

::: details CLIP 是什么？它和多模态大模型是什么关系？
CLIP 用大量图文对训练一个图像编码器和一个文本编码器，让配对的图和文向量靠近、不配对的远离（对比学习）。它本身不生成文字，常用来做图文检索和零样本分类。很多多模态大模型直接拿它的图像编码器做视觉部分，因为它的特征已经和语言语义对齐。
:::

::: details 让模型从截图里提取数据，怎么提高准确率？
给足分辨率，必要时把关键区域裁出来单独发；要求按固定结构输出（见 [结构化输出](/ai/prompt/04-structured-output)），对数字做格式校验；文字很多的场景可以先用 OCR 提取文字，再和图片一起给模型，让它结合版面理解。
:::

::: details 多模态模型能生成图片吗？
这里讲的"看图说话"类模型输出的是文本。生成图片通常由扩散模型等专门的模型完成，或者由能输出图像 token 的统一模型完成。一个产品里两者常被串联：语言模型理解需求、写好描述，再调用图像生成模型。
:::

## 易错点

- 以为 LLM 直接处理像素，实际上它处理的是视觉编码器和投影层产出的向量
- 只看"支持图片输入"，没算图片占用的 token，成本和上下文长度都会超出预期
- 把模型看图得出的数字直接当真，不做校验
