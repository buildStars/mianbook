# 模型蒸馏是什么？怎么用大模型训练出好用的小模型？

::: tip 一句话回答
蒸馏是让小模型（学生）去**模仿大模型（教师）的输出**，而不只是学标注答案。经典做法用教师输出的**完整概率分布（软标签）**做目标，配合**温度**把"第二像的答案是什么"这类信息放大，用 KL 散度作为损失。在 LLM 应用里更常见的是**黑盒蒸馏**：用大模型批量生成高质量的回答或推理过程，作为训练数据给小模型做 SFT。目标是在某个具体任务上，用更低的成本和延迟接近大模型的效果。
:::

## 详细解析

### 为什么软标签比硬标签有用

硬标签只告诉学生"正确答案是 A"。教师的概率分布还告诉它"A 最像，C 比 B 像，D 完全不像"，这些类别之间的相似关系就是额外的知识。

但训练好的教师往往非常自信，第一名接近 1，其余几乎是 0。于是在 softmax 前把 logits 除以温度 T：T 越大，分布越平，次要的信息越明显。

```ts
function softmax(logits: number[], T = 1): number[] {
  const scaled = logits.map((z) => z / T)
  const m = Math.max(...scaled)
  const e = scaled.map((z) => Math.exp(z - m))
  const sum = e.reduce((a, b) => a + b, 0)
  return e.map((x) => x / sum)
}

// KL(p || q)：学生分布 q 离教师分布 p 有多远
const kl = (p: number[], q: number[]) => p.reduce((s, pi, i) => s + pi * Math.log(pi / q[i]), 0)

const teacher = [6.0, 3.5, 3.0, -1.0] // 教师对 4 个候选的 logits
const student = [4.0, 1.0, 2.5, 0.5]

console.log(softmax(teacher, 1).map((p) => p.toFixed(3))) // [ '0.883', '0.072', '0.044', '0.001' ]
console.log(softmax(teacher, 4).map((p) => p.toFixed(3))) // [ '0.458', '0.245', '0.217', '0.080' ]

// 蒸馏损失：两边用同一个温度，乘 T² 让梯度量级和 T 无关
const T = 4
console.log((T * T * kl(softmax(teacher, T), softmax(student, T))).toFixed(4)) // 0.7398
```

实际训练常把这个蒸馏损失和普通的交叉熵损失（对硬标签）加权相加。

### LLM 里的两种蒸馏

| 方式 | 需要什么 | 做法 | 适用 |
| --- | --- | --- | --- |
| 白盒（logits 蒸馏） | 教师每个位置的概率分布，通常要求两者用同一套分词 | 逐 token 让学生的分布贴近教师 | 自己训练的模型家族，大改小 |
| 黑盒（数据蒸馏） | 只需要教师生成的文本 | 用教师的回答构造训练集，对学生做 SFT | 教师只能通过 API 调用时，应用团队最常用 |

推理模型常用黑盒方式把长思考过程蒸馏给小模型，见 [推理模型](/ai/llm/10-reasoning-models)。

### 应用团队怎么落地

1. **定任务**：蒸馏适合范围明确的任务，比如分类、抽取、固定格式的改写。想让小模型全面接近大模型，几乎做不到
2. **收集输入**：尽量用真实的线上请求，覆盖各种边界情况
3. **教师生成**：用大模型加上仔细调过的提示词生成答案，必要时让它多生成几份再挑选
4. **过滤**：用规则校验、评测模型打分或人工抽检去掉错误样本。学生会把教师的错误一起学走
5. **训练学生**：通常用 LoRA 做 SFT，见 [微调、RAG 和 Prompt 工程怎么选](/ai/llm/09-finetune-vs-rag)
6. **评测**：在留出的测试集上和教师对比，同时看延迟和成本，上线后继续抽样对比

### 和量化、剪枝的区别

三者都是为了让模型更便宜，但做法不同：

- **蒸馏**：训练一个新的、结构更小的模型
- **量化**：模型结构不变，把权重从 16 位降到 8 位、4 位，主要省显存和带宽
- **剪枝**：去掉不重要的权重、注意力头或层，之后通常要再训练恢复效果

它们可以叠加：先蒸馏出小模型，再量化部署。

## 面试官可能追问

::: details 学生能超过教师吗？
在特定任务上有可能，比如教师生成多份答案后经过严格筛选，学生学到的是"教师最好的那部分"；或者训练数据比教师见过的更贴近这个任务。但整体能力上，学生一般不会超过教师。
:::

::: details 用别家大模型的输出训练自己的模型，要注意什么？
先看服务条款。不少商业模型的使用条款限制用其输出训练有竞争关系的模型。合规之外，还要注意输出中可能带有的错误、偏见和隐私数据，过滤后再用。
:::

::: details 温度 T 怎么选？
没有通用值，通常在几个候选值里用验证集挑。T 太小，软标签接近硬标签，额外信息少；T 太大，分布过于平坦，正确答案的信号被稀释。
:::

## 易错点

- 只用教师的输出、不做质量过滤，把教师的错误也蒸馏了进去
- 期望一个小模型在所有任务上都接近大模型，蒸馏的收益主要在特定任务上
- 把蒸馏和量化混为一谈，量化不训练新模型，结构也不变
