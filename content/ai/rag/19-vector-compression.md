# 向量太占内存怎么办？标量量化、二值量化和降维怎么取舍？

::: tip 一句话回答
先算账：内存约等于 **条数 × 维度 × 每维字节数**，再加上索引本身的开销。**标量量化**把 float32 压成 int8，内存降到 1/4，召回损失通常很小；**二值量化**每维只留 1 个比特，压缩 32 倍，用汉明距离粗筛，必须配合**过采样 + 原始向量重排**才能把召回补回来；**降维**（比如 Matryoshka 嵌入直接截断前面的维度）从源头减少维度。实践中常组合使用：压缩后的向量放内存做粗筛，原始向量放磁盘只用来重排。
:::

## 详细解析

### 先估算内存

一条 1024 维的 float32 向量占 1024 × 4 = 4096 字节。假设有 1 亿条，光原始向量就要约 400 GB，还没算 HNSW 图里每个节点的邻居列表（见 [ANN 索引](/ai/rag/04-ann-index)）。所以压缩之前先问三个问题：

1. 内存瓶颈在向量本身，还是在索引结构
2. 业务能接受多少召回损失
3. 原始向量能不能放到磁盘或对象存储，只在重排时读取

### 标量量化：float32 转 int8

对每一维统计取值范围（最小值和最大值，或去掉极端值后的分位数），把这个范围线性映射到 256 个整数档位。每维从 4 字节变成 1 字节，内存降到 1/4，距离计算也能用整数 SIMD 指令加速。

嵌入向量每一维的取值通常集中在一个不大的区间里，256 档足够区分，所以召回损失一般不大。要注意的是范围要用有代表性的数据统计；新数据分布变化后，超出范围的值会被截断，精度变差。

### 二值量化：只保留符号

每一维大于 0 记 1，否则记 0，1024 维压成 128 字节，压缩 32 倍。距离用**汉明距离**（两个比特串不同的位数）计算，一条 XOR 加一条 popcount 指令就能算完，非常快。

代价是信息丢得多，单独用召回会明显下降，而且效果很依赖嵌入模型：维度高、各维分布接近以 0 为中心的模型更适合，低维模型往往掉得厉害。所以二值量化基本都配两阶段检索：

1. 用二值向量取出 k 的若干倍（过采样）的候选
2. 读出这些候选的原始向量（或 int8 向量），重新算精确相似度
3. 按新分数取前 k 条

过采样倍数是召回和延迟之间的旋钮，要在自己的评测集上调。

### 降维：截断 Matryoshka 嵌入

有些嵌入模型训练时用了 Matryoshka 表示学习：让向量的前 64、128、256……维单独拿出来也能用。这类模型的向量可以直接截断前面的维度，截断后要**重新做 L2 归一化**，再算余弦或点积。对没按这种方式训练的模型，直接截断效果会明显变差，要用 PCA 之类的方法降维，并重新评测。

降维和量化可以叠加：先截断到 256 维，再做 int8 量化，内存是原来的 1/16。

### 怎么取舍

| 方法 | 压缩比 | 召回影响 | 适合场景 |
| --- | --- | --- | --- |
| 标量量化 int8 | 4 倍 | 通常很小 | 默认首选，几乎没有额外复杂度 |
| 二值量化 + 重排 | 32 倍 | 单用明显下降，重排后可补回大部分 | 超大规模、模型维度高且适配二值化 |
| Matryoshka 截断 | 看截断比例 | 截得越短损失越大 | 模型支持截断，想同时省存储和计算 |
| PQ | 可以很高 | 要靠精排补偿 | 超大规模，见 [ANN 索引](/ai/rag/04-ann-index) |

选型时按"先 int8，不够再降维或二值化"的顺序试，每一步都用同一套评测集看 Recall@k 和最终答案质量（见 [RAG 评测](/ai/rag/08-rag-eval)）。

## 代码示例

用二值向量粗筛、原始向量重排（Node.js，演示用的随机数据是假设值）：

```js
// 二值量化：每一维只保留符号，8 维打包成 1 个字节
function toBits(v) {
  const out = new Uint8Array(Math.ceil(v.length / 8))
  for (let i = 0; i < v.length; i++) {
    if (v[i] > 0) out[i >> 3] |= 1 << (i & 7)
  }
  return out
}

function hamming(a, b) {
  let d = 0
  for (let i = 0; i < a.length; i++) {
    let x = a[i] ^ b[i]
    while (x) { d += x & 1; x >>= 1 }
  }
  return d
}

const dot = (a, b) => a.reduce((s, x, i) => s + x * b[i], 0)

// 两阶段检索：先用汉明距离粗筛 k * oversample 个候选，再用原始向量重排
function search(query, docs, k, oversample = 4) {
  const qBits = toBits(query)
  const candidates = docs
    .map((d, id) => ({ id, dist: hamming(qBits, d.bits) }))
    .sort((a, b) => a.dist - b.dist)
    .slice(0, k * oversample)
  return candidates
    .map(({ id }) => ({ id, score: dot(query, docs[id].raw) }))
    .sort((a, b) => b.score - a.score)
    .slice(0, k)
}

// 演示用的随机数据（假设值）
let seed = 42
const rand = () => ((seed = (seed * 1103515245 + 12345) % 2 ** 31) / 2 ** 31) * 2 - 1
const raw = Array.from({ length: 1000 }, () => Float32Array.from({ length: 64 }, rand))
const docs = raw.map(r => ({ raw: r, bits: toBits(r) }))

const query = raw[7].map(x => x + rand() * 0.1)
const exact = raw.map((r, id) => ({ id, score: dot(query, r) })).sort((a, b) => b.score - a.score).slice(0, 5).map(x => x.id)
console.log('精确 top5:', exact.join(','))
console.log('二值粗筛 + 重排 top5:', search(query, docs, 5).map(x => x.id).join(','))
```

在 1000 条 64 维的随机向量上，过采样 4 倍时 top5 和精确结果重合 4 条；调大过采样倍数可以继续提高重合度，代价是多读原始向量。

## 面试官可能追问

::: details 量化后原始向量还要保留吗？
一般要保留。重排需要原始向量；换量化参数或换索引时也要从原始向量重建。原始向量可以放磁盘或对象存储，不占内存，只在重排时按 ID 读取少量候选。
:::

::: details 标量量化的取值范围怎么定？
最简单是每一维取最小值和最大值，但一两个极端值会把范围撑大，浪费档位。常见做法是取分位数（比如去掉两端少量极端值），超出范围的值截断。范围要用有代表性的样本统计，数据分布明显变化后要重新统计并重建。
:::

::: details 量化之后为什么召回下降不明显，最终答案却变差了？
Recall@k 只看候选有没有进前 k，排序细节变了它看不出来。量化会让相似度很接近的文档顺序打乱，如果后面直接按向量分数截断前几条给模型，就可能挤掉真正最相关的那条。加一层原始向量重排或[重排模型](/ai/rag/06-rerank)，并看端到端的答案质量。
:::

## 易错点

- 只算向量本身的内存，忘了 HNSW 图的邻居列表、元数据和副本，实际占用会大不少
- 对普通嵌入模型直接截断维度，或截断后忘了重新归一化
- 二值量化不做过采样和重排，直接用汉明距离的结果，召回掉得很厉害
- 压缩方案只在公开数据集上测，没有用自己的数据和查询评测
