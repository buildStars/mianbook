# 知识库里的文档互相矛盾或已经过时，RAG 怎么处理？

::: tip 一句话回答
要在三个环节一起处理。**入库时治理**：每份文档带上版本、生效时间、来源和权威度等元数据，新版本**替换**旧版本而不是并存，重复内容去重。**检索时过滤和加权**：只检索当前有效的文档，排序时把时效和权威度算进去。**生成时如实呈现**：把每段资料的来源和日期一起交给模型，要求发现冲突时明确指出、优先采用较新的权威来源，**不要自己编折中答案**。再加上冲突样例的评测和过期文档的定期巡检。
:::

## 详细解析

### 问题从哪来

- 同一份制度发了多个版本，旧版没下线，新旧都能被检索到
- 同一件事不同部门各写一份，口径不同，比如产品文档和客服 FAQ 说法不一
- 文档本身没错，但只在某个时间段有效，比如活动规则、去年的价格
- 复制粘贴产生的大量重复内容，挤占了召回名额

模型拿到两段相互矛盾的资料，常见反应是挑一个、混在一起说，或者编一个两边都不得罪的说法，用户很难察觉。这和恶意[数据投毒](/engineering/security/09-data-poisoning)不同，这里的文档都是正常来源，只是缺乏治理。

### 入库时治理

| 元数据 | 用途 |
| --- | --- |
| `doc_id` + `version` | 识别同一文档的不同版本 |
| `effective_from` / `effective_to` | 生效和失效时间，过期后不再参与检索 |
| `source` / `authority` | 来源系统和权威等级，如正式制度高于讨论帖 |
| `owner` / `updated_at` | 负责人和最后更新时间，用于巡检 |
| `status` | 草稿、生效、废止 |

关键动作：

1. **新版本替换旧版本**：同一个 `doc_id` 入库新版时，把旧版的分块删除或标记为废止，不要两版并存。增量更新的具体做法见[索引增量更新](/ai/rag/12-incremental-index)
2. **去重**：内容哈希去掉完全重复的块，近似重复用 MinHash 或向量相似度找出来，保留权威来源的那份
3. **源头修正**：发现两个部门口径冲突，应该推动业务方统一，RAG 层面只能缓解，不能根治

### 检索时过滤和加权

- **过滤**：查询时加元数据条件，如 `status = 生效` 且当前时间在生效区间内。和[权限过滤](/ai/rag/13-permission-filter)一样，最好在向量库里做前置过滤，避免后过滤把结果滤空
- **按时间点查询**：用户问"去年的报销标准"时，过滤条件改成去年那个时间点有效的版本，所以旧版本应该标记废止并保留时间信息，而不是直接删光
- **加权**：在相关性分数上叠加时效和权威度，例如 `最终分 = 相关性 + a × 权威度 + b × 时效衰减`。权重是假设的调参项，要在评测集上调，不能让一篇很新但不相关的文档排到前面

### 生成时如实呈现

把元数据放进上下文，让模型能看到每段资料的出处和日期：

```text
<doc source="员工手册" version="v3" effective="2026-03-01" authority="正式制度">
差旅住宿标准：一线城市每晚不超过 600 元（示例）
</doc>
<doc source="部门 FAQ" updated="2025-06-10" authority="非正式">
住宿标准为每晚 500 元
</doc>
```

提示词里写清规则：资料冲突时，优先采用生效中、权威度高、日期新的来源；**明确告诉用户存在不一致**，并标出各自来源；无法判断时说明情况，建议联系负责人，不要自己给出折中数字。回答中的来源标注见[引用和溯源](/ai/rag/15-citation)。

### 评测和巡检

- 评测集里专门放冲突和过时的样例：新旧两版并存时答对新版本、问历史时答对旧版本、两个同级来源冲突时能指出冲突
- 定期巡检：超过一定时间没更新的文档提醒负责人确认；被用户反馈"过时"的回答反查到具体文档
- 监控检索日志里废止文档的命中情况，如果还在被检索到，说明过滤或下线流程有漏洞

## 面试官可能追问

::: details 只靠给新文档加权，不做过滤可以吗？
不够。加权只是让新文档排得更靠前，旧文档仍可能进入上下文，模型照样可能引用它。对于明确已废止的内容，应该直接过滤掉；加权适合处理"都有效但可信度不同"的情况。
:::

::: details 文档没有任何元数据，历史存量怎么办？
先从能拿到的信息补：文件的修改时间、所在目录、文件名里的版本号和日期。再用模型批量抽取文档里写明的生效日期和版本。对高频被检索的文档优先人工确认。补不全的标记为"来源不明"，在排序中降权。
:::

::: details 怎么自动发现知识库里的冲突？
对主题相近的文档块（向量相似度高但来源不同）做两两比对，用模型判断是否在同一问题上给出不同结论，产出待处理清单交给负责人。这个成本较高，适合离线定期跑，或只在高频问答涉及的主题上跑。
:::

## 易错点

- 新版本入库时旧版本没下线，新旧两版并存
- 直接删掉旧版本，导致"按历史时间查询"无法回答
- 上下文里不带来源和日期，模型没有任何依据判断谁更可信
- 让模型在冲突时"综合两个说法"，结果得到一个哪份文档都没写过的答案
