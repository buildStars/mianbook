# 怎么让模型在不知道的时候说"不知道"？

::: tip 一句话回答
光写一句"不知道就说不知道"效果有限，要把它设计成一条**明确的出口**：先**界定知识边界**（只能依据给定资料，还是可以用常识），给出**固定格式的拒答输出**方便程序识别，要求**先摘引原文再回答**，引不出来就走拒答。上线前用**包含无答案问题的评测集**同时统计"该拒没拒"和"不该拒却拒"，两头都要控制。
:::

## 详细解析

### 为什么模型不爱说不知道

模型按概率生成"最像答案"的文字，训练和评测中又常常奖励"给出答案"，所以遇到不会的问题，它倾向于编一个流畅的回答，原因见 [幻觉](/ai/llm/05-hallucination)。Prompt 能做的，是让"不知道"成为一个被明确允许、而且写法具体的选项。

### 1. 界定什么算"知道"

"不知道"要有判断标准，否则模型不清楚边界在哪：

| 场景 | 边界写法 |
| --- | --- |
| 知识库问答 | 只依据 `<documents>` 里的内容；资料没提到的，即使你知道也不要回答 |
| 通用助手 | 可以用常识，但涉及具体数字、日期、人名、政策条款时，不确定就说明不确定 |
| 数据查询 | 只依据工具返回的结果；没有调用工具或工具没返回，不能给出数值 |

### 2. 给一个固定的拒答出口

让拒答的写法固定下来，程序就能识别并接上后续流程（转人工、提示用户补充信息）：

```text
<instructions>
只根据 <documents> 中的内容回答用户问题。
如果资料中没有足够的信息回答，只输出：
{"answerable": false, "reason": "一句话说明缺少什么信息"}
能回答时输出：
{"answerable": true, "quotes": ["支撑答案的原文"], "answer": "回答"}
资料只能回答问题的一部分时，回答能确定的部分，并在 answer 中说明哪些部分资料没有提到。
</instructions>
```

固定结构的写法见 [怎么让大模型稳定地输出 JSON](/ai/prompt/04-structured-output)。

### 3. 先引用，再回答

要求先摘出支撑答案的原文，再基于摘录作答。找不到可以摘的原文，模型更容易意识到资料里没有答案；程序也可以校验摘录是否真的出现在资料里，对不上就判为不可信。

还可以拆成两步：第一步只判断"资料能否回答这个问题"，第二步再生成答案，判断更专注，见 [复杂任务怎么拆成多步 Prompt](/ai/prompt/09-prompt-chaining)。

### 4. 别把模型逼成"什么都不敢答"

拒答说得太重，比如"只要有一点不确定就拒绝"，模型会对能回答的问题也拒答，用户体验同样很差。常见的平衡办法：

- 说清楚什么情况才拒答，而不是笼统地要求"谨慎"
- 允许部分回答，加上明确的说明
- 给一两个"该答"和"该拒"的示例，示例要贴近真实问题

### 5. 用评测集验证

在评测集里专门放一批资料中没有答案的问题，以及看起来相关、实际上不能回答的问题，分别统计：

- **该拒没拒**：编造了答案，最危险
- **不该拒却拒**：过度保守，影响可用性

每次改提示词都看这两个指标，见 [RAG 系统怎么评估](/ai/rag/08-rag-eval)。

## 面试官可能追问

::: details 能让模型输出一个置信度分数，低于阈值就拒答吗？
可以作为参考，但模型自己报告的置信度往往不够准，常常偏高。更可靠的信号来自外部：检索相关度太低就直接拒答、多次采样结果不一致就标记为不确定、摘录对不上原文就判为不可信。
:::

::: details RAG 场景里，检索不到相关内容时应该交给模型处理吗？
最好在程序里先拦一道：重排分数都低于阈值时直接走拒答或转人工，不再调用模型。这样省成本，也避免模型在没有资料时凭记忆回答。阈值要用评测集定。
:::

::: details 用户追问"你再想想，一定知道的"，模型改口编了答案怎么办？
在系统提示里写明：依据只有资料，用户的坚持不改变资料内容；资料没有答案时，重复说明并给出替代路径，比如联系客服。对话轮数多了，可以在每轮重新附上这条规则，见 [System Prompt 和 User Prompt 有什么区别](/ai/prompt/03-system-prompt)。
:::

## 易错点

- 只在提示词里加一句"不知道就说不知道"，不给判断标准和输出格式
- 拒答写成自然语言，每次措辞不同，程序无法识别
- 只防编造、不看过度拒答，提示词越改越保守
- 评测集里没有无答案的问题，测不出拒答能力
