# 提示词怎么做版本管理和上线？

::: tip 一句话回答
把提示词当成**代码**管理：放进仓库或专门的提示词管理平台，每次修改都有**版本号**和变更说明，并和**模型版本、参数**绑定在一起。上线前在**评测集**上跑回归，和当前线上版本对比；上线时先**灰度**或做 A/B，每条请求的日志记录**用的是哪个提示词版本**；指标变差时能**一键回滚**。
:::

## 详细解析

### 为什么提示词需要版本管理

提示词改一个字，输出就可能变化，而且不会像代码那样编译报错。常见事故：

- 有人在后台直接改了线上提示词，某类问题开始答错，没人知道改了什么
- 为修一个 bad case 加了一句话，另一类请求的格式坏了
- 模型服务升级后，原来好用的提示词效果下降
- 线上出问题想回到上周的版本，但旧版本没留下来

### 版本里应该包含什么

一个"提示词版本"不只是文本，凡是会影响输出的都要一起固定：

| 内容 | 说明 |
| --- | --- |
| 模板文本 | system prompt、用户消息模板、示例 |
| 模板变量 | 有哪些变量、哪些必填，渲染规则 |
| 模型和参数 | 模型标识、temperature、最大输出长度等 |
| 输出约束 | JSON Schema、工具定义 |
| 元信息 | 版本号、作者、变更说明、对应的评测结果 |

模型标识尽量用固定版本，不用会自动升级的别名，否则提示词没改，效果也可能变。

### 存放方式

- **放在代码仓库**：和代码一起评审、一起发布，有完整的历史记录。缺点是改提示词要走发版流程
- **提示词管理平台**：支持在线编辑、版本对比、按环境发布，产品和运营也能参与。代码运行时按名称和版本或环境标签拉取，并要做本地缓存，平台不可用时仍能工作

两者可以结合：平台上编辑和试验，发布时生成一个不可变的版本号，生产环境只引用明确的版本。

### 上线流程

```text
修改提示词 ──→ 本地试几个样例 ──→ 评测集回归（与线上版本对比）
                                       │
                         指标不降、bad case 修复
                                       ↓
              评审（看 diff 和评测报告）──→ 灰度 5% 流量 ──→ 观察线上指标
                                                               │
                                              正常 → 逐步放量到全量
                                              变差 → 回滚到上一版本
```

1. **评测集回归**：覆盖主要场景、历史 bad case 和边界输入，按维度出分数，见 [同样的输入，模型输出不稳定怎么办](/ai/prompt/10-output-stability)
2. **评审**：像代码评审一样看文本 diff，同时看评测报告
3. **灰度或 A/B**：按用户或请求比例分流，比较格式错误率、用户反馈、转人工率、成本和延迟
4. **可观测**：每条请求记录提示词版本、模型、token 用量和输出，出问题时能按版本筛选

### 回滚

线上只引用"环境 → 版本号"的映射，回滚就是把映射改回上一个版本，不需要重新部署代码。旧版本永远保留，不能被修改或删除。

## 面试官可能追问

::: details 评测集怎么来？怎么判断新版本更好？
从线上日志里抽样真实请求，加上收集到的 bad case 和人工构造的边界情况，标注期望结果或评分标准。能用规则判断的（格式、字段、关键词）用规则；开放式回答可以用模型打分并定期人工校准。新版本要在主要指标上不低于线上版本，而且修复了目标问题。
:::

::: details 运营同学想直接改提示词，怎么管？
给他们平台上的编辑和试验权限，但发布到生产必须经过评测和审批。可以把提示词中经常变化的部分（话术、活动信息）拆成变量或配置，核心规则仍由工程侧维护。
:::

::: details 多个提示词串联的链路怎么做版本管理？
每个环节有自己的版本，再给整条链路定义一个组合版本，记录各环节用的是哪个版本。评测时既测单个环节，也测端到端结果，避免改了上游、下游的输入分布变了没人发现，见 [复杂任务怎么拆成多步 Prompt](/ai/prompt/09-prompt-chaining)。
:::

## 易错点

- 只管理提示词文本，不固定模型版本和参数，复现不了当时的效果
- 只用几个手工例子判断改得好不好，不跑完整的回归评测
- 日志里没记录提示词版本，出了问题分不清是哪次改动导致的
