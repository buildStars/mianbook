# Agent Skills 是什么？和工具、MCP 有什么区别？

::: tip 一句话回答
Agent Skills 是把**完成某类任务所需的指令、脚本和参考资料打包成一个文件夹**，核心是一个带元数据的 `SKILL.md`。它靠**渐进式披露**省上下文：启动时只加载每个技能的名称和描述，任务相关时才读入正文，正文里提到的脚本和文档再按需读取或执行。**工具**给 Agent 一个可调用的动作，**MCP** 是接入外部工具和数据的协议，**Skill** 则是"怎么做这件事"的知识和流程，通常还要借助文件系统和代码执行环境来用。
:::

## 详细解析

### 一个技能长什么样

```text
pdf-report/
├── SKILL.md          # 必需：元数据 + 操作说明
├── reference.md      # 可选：详细参考，需要时再读
├── templates/        # 可选：模板、示例
└── scripts/
    └── fill_form.py  # 可选：确定性的脚本，直接执行
```

`SKILL.md` 开头是 YAML 元数据，至少有 `name` 和 `description`。description 要写清"做什么、什么时候用"，因为模型就靠它决定要不要加载这个技能：

```markdown
---
name: pdf-report
description: 填写和生成 PDF 报表。用户要求填 PDF 表单、合并 PDF 或导出报表时使用。
---

# PDF 报表
1. 先运行 scripts/fill_form.py --check 检查表单字段
2. ……
表单字段的含义见 reference.md。
```

### 渐进式披露

| 层级 | 何时进入上下文 | 内容 |
| --- | --- | --- |
| 元数据 | Agent 启动时，所有技能都加载 | name 和 description，每个技能很短 |
| 正文 | 判断任务相关时 | `SKILL.md` 里的步骤和规范 |
| 附带资源 | 正文指向且确实需要时 | 参考文档按需读；脚本直接执行，只有输出进上下文 |

这样装几十个技能，平时也只占少量 token。相比把所有规范都塞进 System Prompt，上下文更干净，也更不容易互相干扰。这是[上下文工程](/ai/prompt/05-context-engineering)里"按需加载"思路的一种具体形式。

脚本的价值在于确定性：排序、格式转换、校验这类工作让代码做，比让模型每次现写代码更稳，也更省 token。

### 和工具、MCP、System Prompt 的区别

| | 本质 | 解决的问题 | 加载方式 |
| --- | --- | --- | --- |
| 工具 | 一个带 Schema 的函数 | Agent 能执行某个动作 | 定义常驻在请求里 |
| MCP | 连接协议 | 用统一方式接入外部工具、资源和提示词 | 连接服务后暴露工具等 |
| Skill | 指令 + 脚本 + 资料的打包 | Agent 知道某类任务的流程和规范 | 渐进式，按需读取 |
| System Prompt | 固定指令 | 全局身份、规则 | 每次都在 |

几者是叠加关系：一个"提交报销单"技能可以写明"先用 MCP 接入的财务系统工具查额度，再运行本地脚本生成单据"。工具和 MCP 给的是"手"，Skill 给的是"手册"。工具多到选不过来的问题见[工具数量太多怎么办](/ai/tools/10-many-tools)，Skill 不能替代那里的工具检索，但能把大量流程知识移出常驻上下文。

### 第三方技能的安全风险

技能能带可执行脚本，正文还会被当成指令读进去，所以装一个技能约等于装一个软件包：

- 正文里可能藏着恶意指令，诱导 Agent 泄露数据或执行危险操作，本质是[提示词注入](/engineering/security/01-prompt-injection)
- 脚本可能直接读密钥、联网外传
- 引用外部链接的技能，内容可能在你审核后被替换

做法：只装可信来源的技能，安装前通读全部文件；脚本在[沙箱](/engineering/security/06-sandbox)里运行，限制网络和文件访问；企业内用私有技能库统一审核和版本管理。

## 面试官可能追问

::: details 技能写好了但 Agent 不触发，怎么排查？
大多数是 description 写得太泛或没写触发场景。改成"做什么 + 用户说什么时用"，带上用户常用的说法。也要检查多个技能描述是否重叠，导致模型选了别的。可以准备一批测试请求，统计技能被正确触发的比例。
:::

::: details 什么时候该写成技能，什么时候直接写进 System Prompt？
每次对话都要遵守的规则放 System Prompt，比如身份、语气、安全底线。只在特定任务才用、篇幅又长的流程和规范做成技能，比如某种报表的格式要求、某套代码库的发布步骤。
:::

::: details 没有代码执行环境的 Agent 能用技能吗？
纯指令部分可以，靠读文件或检索把正文放进上下文就行。但脚本类资源需要能执行代码的环境才能发挥作用，渐进式读取也依赖 Agent 能按路径读文件，所以技能最适合有文件系统和沙箱的 Agent。
:::

## 易错点

- 把 Skill 当成又一种工具协议。它不定义调用接口，主要是给模型看的说明和可执行资源
- description 只写名字不写场景，导致该用时不加载
- 把所有内容都塞进 `SKILL.md`。详细资料应拆到单独文件，正文只放主流程和指引
- 不审核就装第三方技能。脚本和指令都可能是攻击面
