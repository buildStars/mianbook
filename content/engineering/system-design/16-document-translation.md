# 设计一个保留格式的文档翻译系统

::: tip 一句话回答
核心思路是**只翻译文字，不碰结构**：把 Word、PPT、PDF 等文档解析成"结构树 + 文本片段"，片段里的加粗、链接等行内格式用**占位标记**保护起来，翻译后校验标记完整，再写回原来的位置重建文档。翻译按段落分批，带上**前后文**和**术语表**保证一致；片段之间相互独立，可以大量**并发**，相同片段走缓存去重。质量上用自动检查（标记、数字、术语、漏译）兜底，重要文档再**人工校对**，校对结果回流到术语表和翻译记忆。
:::

## 详细解析

### 需求澄清

- 输入格式：Word、PPT、Excel、PDF、Markdown、HTML；不同格式难度差别很大
- 规模：单个文档从几页到几百页；需要异步处理，显示进度
- 质量：格式尽量和原文一致；专有名词前后统一；数字、代码、链接不能被改
- 和 [超长文档的总结问答](/engineering/system-design/07-document-processing) 的区别：那里要理解和压缩内容，这里要**逐句对应**，且输出必须还原成原格式

### 整体架构

```text
上传 → 格式识别 → 解析器（按格式）→ 中间表示（结构树 + 文本片段）
                                          │
                     片段切分、合并成批、查翻译记忆和缓存
                                          │
                        翻译 Worker（并发，带术语表和上下文）
                                          │
                       自动校验（标记、数字、术语、长度）──不通过──> 重试 / 标记人工
                                          │
                       写回结构树 → 重建器（按格式）→ 版面检查 → 下载 / 人工校对
```

### 核心模块和数据模型

**解析和中间表示**：

- Word、PPT、Excel 本质是压缩包里的 XML，可以解析出段落、文字片段及其样式；PDF 没有段落结构，要先做版面分析，重建难度最大（解析见 [多模态解析](/ai/rag/11-multimodal-parsing)）
- 片段记录 `{ docId, segmentId, path, sourceText, tags[], context }`，`path` 指向在原文档结构里的位置，写回时按它定位
- 一个段落里常常有多段不同样式的文字，例如中间有一个加粗词。如果按样式拆开分别翻译，语序一变就错了

**行内格式保护**：把段落合并成一句话，行内格式换成成对的占位标记，例如 `点击 <b1>保存</b1> 按钮`。要求模型保留标记，翻译后按标记把样式映射回去。代码、URL、变量名、数字也可以替换成占位符，翻译后再还原。

**分段和上下文**：以段落为单位，几个相邻段落合成一批，减少请求数；同时附上前后一两个段落作为只读上下文，帮助处理代词和省略。表格单元格很短，合成一批时要保留单元格边界。

**术语表和一致性**：

- 术语表按客户或项目维护，翻译时只把本批出现的术语放进 Prompt，而不是整张表
- **翻译记忆**：已经确认过的句对存起来，完全相同的句子直接复用，相似的作为参考
- 全文级检查：同一个术语在全文的译法是否统一，不统一的标出来

### 关键难点

**格式还原**：

- 译文长度和原文不同，PPT 的文本框、表格单元格可能放不下。可以要求简洁翻译，或者按比例缩小字号，重建后渲染成图片检查溢出
- 从右到左书写的语言要调整段落方向
- 页眉页脚、脚注、批注、图表里的文字容易漏掉，解析时要覆盖全；图片里的文字要单独 OCR 后处理，或者明确告知不翻译

**并发和成本**：

- 片段之间独立，按批并发翻译，受模型接口限流约束（见 [限流和降级](/engineering/deploy/08-rate-limit-fallback)）
- 相同片段（页眉、重复的表头）只翻一次；术语表和系统提示放在前缀，便于命中 [Prompt Caching](/engineering/deploy/04-prompt-caching)
- 不着急的大文档可以走 [Batch 接口](/engineering/deploy/12-batch-api)
- 任务按片段记录进度，Worker 中断后从未完成的片段继续，不用整篇重来

**质量评估**：

- 规则检查：占位标记数量和配对、数字和单位、术语是否用了指定译法、是否有未翻译的原文残留、长度比例异常
- 抽样用模型做评审（见 [LLM-as-Judge](/engineering/eval/02-llm-as-judge)），评忠实度和流畅度
- 人工校对界面左右对照显示原文和译文，修改直接写回片段，再重新生成文档

### 扩展与优化

- 按领域选择不同的提示和模型，法律、医疗文档用更强的模型并强制人工校对
- 人工修改的句对回流进翻译记忆，客户特有的术语自动建议加入术语表
- 支持只翻译增量：文档更新后，按片段的哈希找出变化部分，只翻译改过的段落

## 面试官可能追问

::: details 为什么不直接把整个文件内容丢给模型翻译？
文件格式的原始内容大部分是结构和样式，模型改动或漏掉一个标签，文件就可能打不开；长文档也超出单次输出能力，失败后只能整篇重来。把文字抽出来分段处理，格式由程序保证，模型只负责翻译。
:::

::: details 模型把占位标记弄丢了或位置错了怎么办？
先校验：标记数量不对或配对错误，带着错误提示重试一次；还不行就降级，去掉行内样式只保留文字，或者交给人工。标记的位置在语序变化后可能不完全准确，这是可以接受的小瑕疵，重要文档靠人工校对。
:::

::: details 怎么保证几百页文档里同一个术语前后一致？
三层：翻译前用术语表约束；翻译中给每批带上已经确定的译法；翻译后全文扫描同一个原文术语的所有译法，不一致的统一或者标出来让人决定。
:::

## 易错点

- 按样式片段逐段翻译，一句话被拆成几截，译文语序混乱
- 没有保护数字、代码和链接，被模型"翻译"或改写
- 只抽正文，漏了表格、页眉、批注、图表里的文字
- 不检查译文长度，PPT 里文字溢出文本框
