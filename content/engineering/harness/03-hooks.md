# Agent 的 Hooks 是什么？怎么在工具调用前后插入检查和自动化？

::: tip 一句话回答
Hooks 是 harness 在 Agent **生命周期事件**上开放的扩展点：会话开始、用户提交消息、工具调用前、工具调用后、回复结束等。挂上去的是**确定性的脚本**：调用前可以拦截或改写参数，调用后可以自动格式化、跑检查，再把结果反馈给模型。写在提示词里的要求模型可能忘，hook 每次触发都会执行。
:::

## 详细解析

防失控的整体策略见 [怎么防止 Agent 失控](/ai/agent/07-guardrails)，这里只讲 hooks 这个机制。

### 常见的事件

| 事件 | 典型用途 |
| --- | --- |
| 会话开始 | 注入当前分支、待办事项等动态上下文 |
| 用户提交消息 | 检查是否含密钥，补充上下文 |
| 工具调用前 | 拦截危险命令、改写参数、要求审批 |
| 工具调用后 | 改完文件自动格式化、跑 lint 或类型检查 |
| 回复结束 | 检查任务是否真的完成，没完成就让 Agent 继续 |
| 上下文压缩前 | 保存需要保留的关键信息 |

hook 的输入通常是一段 JSON：事件名、工具名、参数、会话 ID、工作目录等。输出用退出码或 JSON 告诉 harness 下一步。例如有的编程类 Agent 约定：退出码 0 表示正常继续，退出码 2 表示拦截，并把 stderr 作为原因交给模型；其他非零退出码只算 hook 自身出错，默认不拦截；也可以返回 JSON，明确给出允许、拒绝、询问用户或改写后的参数。具体约定各家不同，以产品文档为准。

### 调用前：拦截和改写

- **拦截**：命令删除了工作区外的文件、修改了受保护的目录、提交内容里有密钥，就拒绝并说明原因。模型看到原因后会换一种做法
- **改写**：给命令补上安全参数、把路径限制在工作区内、把全量测试改成只跑相关文件

拦截原因是写给模型看的。"不允许直接改 migrations 目录，请新建一个迁移文件"比一个光秃秃的"拒绝"有用得多。

### 调用后：自动化和反馈

模型改完一个文件，hook 自动跑格式化和 lint。没问题就静默；有错误就把精简的错误信息交给模型，让它下一轮修掉。"代码必须过 lint"就从提示词里的一句要求，变成了每次都会发生的事。

"回复结束"事件也很有用：检查测试是否通过，没通过就阻止结束，让 Agent 接着修。要防止它变成死循环，比如限制最多拦几次。

### 确定性规则和提示词的分工

| | 提示词里的要求 | Hook |
| --- | --- | --- |
| 执行保证 | 模型可能忘记，或被诱导忽略 | 每次触发都执行 |
| 适合 | 风格、偏好、需要理解语义的事 | 能用代码判断的硬规则 |
| 成本 | 占上下文 | 占执行时间 |

能用代码判断的规则就别只靠提示词；需要理解语义的留给模型。

### 超时、失败和安全

- **超时**：hook 卡住会拖住整个 Agent，必须有超时。超时后放行还是拦截要想清楚：安全类 hook 应该失败即拦截，格式化类 hook 失败了可以放行
- **失败处理**：hook 脚本自己出错，要和"hook 判定拦截"区分开，不然一个写错的脚本会让 Agent 寸步难行，或者反过来让检查悄悄失效
- **安全风险**：hook 是以当前用户权限执行的任意命令。仓库里自带的 hook 配置，等于仓库能在你的机器上跑代码，打开不信任的项目前要先审查。hook 读到的工具参数来自模型，拼进 shell 命令前要转义，否则 hook 自己成了注入入口

## 面试官可能追问

::: details Hook 和权限规则有什么区别？
权限规则是声明式的，只能表达"匹配就放行、询问或拒绝"，见 [权限模式](/engineering/harness/02-permission-modes)。hook 是代码，可以做任意判断：读文件内容、调外部服务、改写参数。简单的放行和禁止用规则，复杂的检查用 hook。
:::

::: details 调用后的 hook 能撤销已经执行的操作吗？
不能，工具已经执行完了。它能做的是检查结果、把问题反馈给模型，或者执行补救动作。要阻止的事必须在调用前拦。
:::

::: details Hook 的输出会进入上下文吗？
看设计。拦截原因和检查错误通常要交给模型，这正是 hook 起作用的方式；但正常情况下的冗长输出不该进上下文，否则白白占用窗口。成功时静默、失败时给精简的错误，是比较好的做法。
:::

## 易错点

- 把 hook 当成唯一的安全边界，它只是一个扩展点，沙箱和权限规则仍然需要
- 安全类 hook 超时或报错时默认放行，等于没拦
- 把模型给的参数直接拼进 shell 命令，hook 本身被注入
- 打开陌生仓库时不加审查就执行仓库里配置的 hook
