# Token 用量怎么监控？预算告警怎么做？

::: tip 一句话回答
每次调用都把响应里的 **usage**（输入、输出、缓存命中的 token 数）连同**租户、用户、功能、模型**等维度记下来，按单价折算成成本，汇总到报表里。预算控制分两层：**告警**是软阈值，用量达到预算的一定比例时通知负责人；**限额**是硬阈值，超出后降级到便宜模型或拒绝请求。还要做**异常检测**：Agent 死循环、被盗用的密钥、某个功能突然暴涨，往往是一夜之间花掉一个月预算的原因。
:::

## 详细解析

### 记什么

每次调用落一条用量记录：

| 字段 | 说明 |
| --- | --- |
| 时间、请求 id、trace id | 能和链路追踪对上（见 [链路追踪](/engineering/eval/07-tracing)） |
| 租户、用户、功能 | 成本归属的维度，决定能不能回答"钱花在哪了" |
| 模型、配置版本 | 换模型后的成本变化要能看出来 |
| 输入、输出、缓存命中 token 数 | 以 API 返回的 usage 为准，不用自己估算 |
| 成本 | 按记录时的单价折算，单价放配置表里，不写死在代码中 |
| 状态 | 成功、失败、中断；失败和中断的请求也可能产生费用 |

流式响应的 usage 位置因接口而异：OpenAI Chat Completions 要设置 `stream_options: {"include_usage": true}`，usage 才会出现在最后一个 chunk 里；Anthropic 在开头的 `message_start` 事件里给出输入 token，输出 token 在 `message_delta` 事件里累计更新。用户中途停止时，输出用量可能拿不全，这时只能按已收到的内容估算，并标记为估算值。单次成本怎么算见 [成本估算](/engineering/deploy/02-cost-estimate)。

### 统计和看板

用量记录写入日志或消息队列，异步聚合到时序库或分析库，不要在请求链路里同步写重的报表。看板至少有：按天的总成本趋势、各功能和各租户的成本排行、每次请求的平均 token 数、缓存命中率。

### 预算的软硬阈值

```text
用量 < 80%   正常
用量 ≥ 80%   告警：通知负责人
用量 ≥ 100%  限额：降级到便宜模型 / 只服务付费用户 / 拒绝新请求
```

比例只是示意，按业务定。限额的执行要放在网关里，在请求发出前检查。高并发下精确扣减很难，常见做法是：

- 用 Redis 之类的计数器按租户累加当期用量，请求前检查、请求后累加
- 对单次可能很贵的请求先**预扣**一个估算值，结束后按实际 usage 多退少补
- 接受少量超额：计数有延迟，硬限额允许一点误差，月底以账单为准对账

### 异常检测

- **单次请求过大**：输入 token 远超正常值，可能是上下文没截断或被人塞了超长文本
- **单个会话调用次数过多**：Agent 陷入循环，要设最大步数和单任务 token 上限（见 [防止 Agent 失控](/ai/agent/07-guardrails)）
- **单个用户或密钥突增**：可能是脚本刷接口或密钥泄露（见 [API Key 安全](/engineering/security/07-api-key)）
- **和同期比较**：比如成本比上周同一天高出很多就告警，比固定阈值更适合有增长的业务

服务商控制台通常也能设置用量上限和告警，作为最后一道兜底，但它看不到你的业务维度。

## 面试官可能追问

::: details 为什么不能只看服务商的账单？
账单只有按模型或按密钥的汇总，不知道是哪个功能、哪个租户花的钱，也往往有延迟。要做成本归因、给租户计费、实时限额，都得自己记录。服务商账单用来月底对账。
:::

::: details 多租户场景下怎么给租户计费？
用量记录带上租户 id，按租户聚合 token 和成本，再乘以定价规则（可能和你的采购成本不同）。计费记录要可追溯到每次请求，方便处理租户的账单异议。
:::

::: details 流式请求被用户中断，usage 拿不到怎么办？
可以按输入的 token 数加已收到的输出估算，记录时标记为估算值。月底和服务商账单对账时，看估算值的误差有多大。
:::

## 易错点

- 用量记录没有业务维度，只知道花了多少，不知道花在哪
- 只统计成功的请求，失败重试和中断的消耗被漏掉
- 单价写死在代码里，价格调整后历史成本和新成本都算错
- 只设告警不设硬限额，或者限额检查放在业务里，绕过网关的调用不受控
