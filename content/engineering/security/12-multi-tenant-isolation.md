# 多租户 AI 应用怎么做数据隔离？

::: tip 一句话回答
多租户 AI 应用的数据不止数据库一处：**向量库、会话记忆、缓存（尤其是语义缓存）、日志和评测数据、微调数据、工具凭证**都可能串租户。原则是**租户身份来自服务端的登录态**，每一层的读写都由代码强制带上租户条件，不靠提示词让模型"只回答本公司的内容"。隔离强度可以按租户等级选：共享库加租户字段、每租户独立分区或集合、每租户独立实例，越往后越安全，成本也越高。
:::

## 详细解析

### 数据会从哪里串

| 位置 | 串租户的方式 |
| --- | --- |
| 向量库 | 检索时漏了租户过滤条件，召回了别的租户的文档片段 |
| 会话记忆 | 长期记忆、摘要按用户存，但用户 ID 在租户间不唯一，或 key 拼错 |
| 语义缓存 | 只按问题的相似度命中，A 公司的回答被返回给 B 公司 |
| 日志和评测 | 完整的提示词和回答落到共享日志，被其他租户的运维或评测流程看到 |
| 微调 | 用多个租户的数据训练一个共享模型，模型可能在回答中复述训练数据 |
| 工具和 Agent | 工具使用共享凭证，Agent 能访问所有租户的系统 |

传统 SaaS 的隔离主要守住数据库；AI 应用多了检索、缓存、记忆和模型本身这几层，任何一层漏了，敏感内容就会被模型直接写进回答里。

### 原则：隔离在代码里强制执行

- **租户 ID 来自认证信息**，不从请求参数、更不从模型生成的工具参数里取
- **数据访问层统一注入租户条件**：业务代码拿不到"不带租户过滤"的检索接口，避免每个调用点自己记得加
- **写入时打标**：文档入库时就写入租户 ID，切块、向量化后的每个片段都继承它
- **提示词不是边界**：在 System Prompt 里写"只回答本租户内容"挡不住检索层已经召回的数据，见 [大模型应用怎么防止敏感信息泄露](/engineering/security/04-data-leakage)

### 向量库的三种隔离方式

| 方式 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 共享集合加元数据过滤 | 所有租户在一个集合里，查询时按 tenant_id 过滤 | 成本低，租户多时好管理 | 依赖每次查询都带过滤；过滤和近似检索结合时要确认召回质量 |
| 每租户一个分区、命名空间或集合 | 查询时只在该租户的范围里搜 | 隔离清晰，删除租户数据简单 | 租户很多时管理和资源开销上升 |
| 每租户独立实例或独立库 | 物理隔离 | 隔离最强，满足合规要求 | 成本最高，运维复杂 |

常见做法是分级：普通租户共享集合，大客户或有合规要求的租户独立部署。用关系数据库存向量时（例如 PostgreSQL 加向量扩展），可以再加一层**行级安全策略**，即使应用层漏了条件，数据库也会拦住。

### 缓存、记忆和日志

- 缓存的 key 和语义缓存的检索范围都要**带上租户 ID**，见 [语义缓存](/engineering/deploy/10-semantic-cache)
- 记忆按"租户 + 用户"组合存储，删除租户时能一起清掉
- 日志按租户分开存放和授权，敏感字段脱敏；用线上数据做评测前要获得授权并去标识
- 微调优先每租户单独训练（如 LoRA 适配器按租户加载），不要把多家数据混训成一个共享模型

### 验证隔离是否有效

隔离最怕"以为做了"。可以在测试环境建两个租户，用 A 的账号构造各种请求去拿 B 的数据：直接提问、换说法、让 Agent 调工具、命中缓存，确认全部拿不到。这类用例放进回归测试，每次改动检索或缓存逻辑都跑一遍。

## 面试官可能追问

::: details 只在 System Prompt 里告诉模型租户信息，会有什么问题？
模型只能决定怎么用上下文里的内容，管不了上下文里有什么。如果检索已经召回了别的租户的片段，模型可能直接引用；提示注入还能让它无视限制。所以过滤必须在检索之前完成。
:::

::: details 共享集合加元数据过滤，检索质量会受影响吗？
可能会。如果先做近似检索取 top-k 再过滤，过滤后剩下的结果可能很少甚至为空；支持检索时同步过滤的向量库会好一些。租户数据量差异大时要实测召回率，必要时给大租户单独分区。
:::

::: details 租户要求删除全部数据，要删哪些地方？
原始文档、向量片段、会话和记忆、缓存、日志和评测样本、按租户训练的适配器，以及备份的保留策略。入库时统一打上租户标记，删除才能做得完整。
:::

## 易错点

- 只隔离了业务数据库，忘了向量库、缓存、日志这些 AI 链路特有的存储
- 让模型生成的工具参数决定 tenant_id，被注入后就能越权
- 语义缓存只按相似度命中，不区分租户
- 用多个租户的数据训练共享模型，训练数据可能在回答中泄露
