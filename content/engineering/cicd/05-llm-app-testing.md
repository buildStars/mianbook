# 大模型应用怎么写自动化测试？模型调用怎么 mock？

::: tip 一句话回答
把应用拆成**确定性部分**和**模型调用**。解析输出、工具执行、上下文组装这些确定性逻辑用普通单测覆盖；模型客户端通过依赖注入换成**假实现**，返回预设回复，或者**录制**一次真实响应后反复回放。对真实模型的输出不比较原文，改用**结构和属性断言**：是不是合法 JSON、字段齐不齐、有没有包含必要信息。CI 里分层跑：每次提交跑单测和回放测试，真实调用的评测按需或定时跑。
:::

## 详细解析

### 先分清哪些是确定的

一个典型的大模型功能，大部分代码其实是确定的：

```text
用户输入 → [组装上下文：检索、拼提示词、截断] → 模型调用 → [解析输出、校验、调用工具、格式化] → 返回
              确定性，普通单测                    不确定        确定性，普通单测
```

- **上下文组装**：给定输入和检索结果，拼出的消息列表是否正确，长度超限时是否按规则截断
- **输出解析**：模型回复带了多余文字、JSON 不完整、字段类型错时能不能正确处理或报错
- **工具执行**：给定一个工具调用参数，工具是否按预期执行，参数非法时是否拒绝

这些测试快、稳定、不花钱，应该是数量最多的一层。

### mock 模型客户端

关键是代码里不要直接 `new` 一个 SDK 客户端，而是把客户端作为参数传进来，测试时换成假实现。假实现可以：

1. **返回预设回复**：专门构造边界情况，比如回复里没有 JSON、字段非法、工具调用参数缺失
2. **记录收到的请求**：断言提示词里带上了用户输入、系统提示和工具定义
3. **模拟错误**：超时、限流、返回空内容，验证重试和降级逻辑

### 录制回放

手写的假回复和真实模型的回复往往不一样。录制回放的做法是：

1. 第一次以录制模式运行，真实调用模型，把请求和响应按请求内容的哈希存成文件
2. 之后的运行直接读文件回放，不联网、结果固定
3. 改了提示词，请求哈希变了，回放找不到记录就报错，提醒重新录制

录下来的文件要提交到仓库并在评审时看一眼，同时注意别把密钥和用户隐私录进去。

### 不确定的输出怎么断言

真实调用时同一个输入每次回复都可能不同，不能 `assertEqual` 原文。可以断言：

- **结构**：能解析成 JSON，符合 schema
- **属性**：包含某些关键词、不包含禁止内容、长度在范围内、引用的文档 ID 确实在检索结果里
- **行为**：该调用工具时调用了正确的工具，参数类型对

更主观的质量（回答准不准、好不好）要靠评测集和打分，那是 [效果回归测试](/engineering/eval/05-regression-testing) 的范围；流式输出的测试见 [流式功能测试](/engineering/streaming/16-stream-testing)。

### 在 CI 里分层

| 层 | 内容 | 什么时候跑 | 失败的含义 |
| --- | --- | --- | --- |
| 单测 + mock | 确定性逻辑、边界情况 | 每次提交 | 代码有 bug，必须修 |
| 录制回放 | 用真实响应样本跑完整链路 | 每次提交 | 链路被改坏，或需要重新录制 |
| 真实调用 | 少量冒烟用例，属性断言 | 合并后、定时 | 可能是模型或服务变化，要人看 |
| 评测集 | 打分、和基线对比 | 改提示词、换模型时 | 效果退化 |

真实调用那一层花钱、慢、会抖，不要放进阻塞每个 PR 的门禁。

## 代码示例

用 Node.js 自带的测试运行器，给解析函数注入假模型：

```js
import { test } from 'node:test'
import assert from 'node:assert/strict'

// 被测代码：依赖注入模型客户端，而不是在函数里直接 new 一个 SDK
async function extractOrder(text, llm) {
  const reply = await llm.chat([
    { role: 'system', content: '把用户输入解析成 JSON：{"item": string, "qty": number}' },
    { role: 'user', content: text },
  ])
  const json = reply.match(/\{[\s\S]*\}/)?.[0]
  if (!json) throw new Error('模型没有返回 JSON')
  const order = JSON.parse(json)
  if (typeof order.item !== 'string' || !Number.isInteger(order.qty) || order.qty <= 0) {
    throw new Error('字段不合法')
  }
  return order
}

// 假的模型客户端：按顺序返回预设回复，并记录收到的消息
function fakeLLM(replies) {
  const calls = []
  return {
    calls,
    async chat(messages) {
      calls.push(messages)
      return replies.shift()
    },
  }
}

test('能解析包在说明文字里的 JSON', async () => {
  const llm = fakeLLM(['好的，结果是：{"item": "咖啡", "qty": 2}'])
  const order = await extractOrder('来两杯咖啡', llm)
  assert.deepEqual(order, { item: '咖啡', qty: 2 })
  // 断言提示词里确实带上了用户输入
  assert.equal(llm.calls[0].at(-1).content, '来两杯咖啡')
})

test('模型返回非法数量时报错', async () => {
  const llm = fakeLLM(['{"item": "咖啡", "qty": -1}'])
  await assert.rejects(extractOrder('来杯咖啡', llm), /字段不合法/)
})
```

## 面试官可能追问

::: details temperature 设成 0 是不是就能直接比较原文了？
不能完全依赖。很多服务即使温度为 0 也不保证每次输出完全一样，模型版本更新后输出也会变。温度调低能减少波动，但断言仍然应该用结构和属性。
:::

::: details 智能体（Agent）的多轮工具调用怎么测？
假模型按顺序返回一串回复：第一轮返回工具调用，第二轮根据工具结果给出最终答案。测试断言工具被调用的顺序和参数、工具结果被正确放回上下文、达到最大轮数时会停下来。
:::

::: details 录制的数据过期了怎么办？
提示词或模型变了就重新录制，并在评审时对比新旧响应的差异。可以定期全量重录，把录制当成一次小规模的回归检查。
:::

## 易错点

- 在业务函数里直接创建 SDK 客户端，测试时没法替换，只能真实调用
- 每个 PR 都真实调用模型，CI 又慢又贵还时不时随机失败
- 用精确字符串断言模型输出，测试一直红，最后大家干脆把它跳过
