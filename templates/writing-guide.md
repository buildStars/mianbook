# 题目写作规范

新题照着 [question.md](question.md) 的模板写，放在 `content/<部分>/<分类>/` 下，文件名是 `两位序号-英文短名.md`（如 `03-stream.md`）。写完运行 `node scripts/check-content.mjs <分类>` 检查格式，再用 `npm run db:import` 导入。

## 结构

```markdown
---
difficulty: 2
tags: [高频, 原理]
---

# 题目（问句，和目录里显示的一致）

::: tip 一句话回答
面试时开口先说的两三句话。
:::

## 详细解析
### 小标题……

## 代码示例          （可选；手写题可以写成"## 代码示例：手写 xxx"）

## 面试官可能追问
::: details 追问的问题？
答案
:::

## 易错点
- ……
```

- **frontmatter** 只写 `difficulty` 和 `tags` 两个字段
  - `difficulty`：1 基础概念，2 常考、需要讲清原理，3 深入原理或开放式设计
  - `tags` 从这些里选 1～3 个：高频、原理、实践、性能优化、场景题、手写题、安全、输出题、综合、系统设计、新特性、新技术、对比
- **一句话回答**：2～4 句，直接给结论，关键词用 `**加粗**`。读者只看这一段也能答个及格
- **详细解析**：用 `###` 分成小节，一般 3～5 个，不超过 6 个。讲清"是什么、为什么、怎么做"，流程用有序列表，对比用表格，架构和流程图放在 ` ```text ` 代码块里。系统设计题按"需求澄清 → 整体架构 → 核心模块和数据模型 → 关键难点 → 扩展与优化"五步组织
- 表格单元格里的 `|` 即使在反引号里也要写成 `\|`，否则会被当成分列符
- **代码示例**：代码要能运行、写法要符合当前主流版本；注释用中文，只注释关键的地方；代码块必须标语言（js、ts、vue、jsx、tsx、sql、bash、json、yaml、nginx、python、text 等）
- **面试官可能追问**：3～4 个，问题是面试官真的会接着问的，答案 2～5 句。`details` 里不要再嵌套 `:::` 容器，可以放代码块
- **易错点**：2～4 条，写容易答错、混淆或踩坑的地方
- 全文 60～140 行；系统设计题可以长一些，但不超过 170 行

## 文风

- 简体中文，短句，陈述句。像经验丰富的同事在讲解，不是写论文，也不是写营销文案
- 不用这些口头禅：首先、其次、总之、值得注意的是、综上所述、众所周知
- 引号统一用英文直引号 `""`，不用中文弯引号
- 中文和英文、数字之间加空格（如 `Node.js 的 Stream`）
- 正文里出现 HTML 标签、`{{ }}` 时要用反引号包起来，否则会被当成正文渲染
- 正文不用 emoji；代码注释里可以用 ✅ / ❌ 标出正确和错误的写法

## 准确性

- 只写有把握的内容。拿不准的细节宁可不写，也不要猜
- 不编造数据：没有可靠来源的性能数字、比例、价格都不写；必须举例计算时，明确说明是假设值
- 变化快的领域（模型、框架、云服务）只写稳定的概念。提到产品时用"例如"，不写版本号、发布时间、价格、排名和"最新""最强"这类会过时的说法
- 代码中用到的 SDK 或 API 要和官方文档一致；不确定时写成通用的伪接口（如 `llm.chat(...)`），并说明各家写法不同
- 内容原创，不照搬书籍、付费课程或博客的原文

## 链接

站内链接写成 `[事件循环](/basics/javascript/01-event-loop)`，路径是 `/部分/分类/文件名`，不带 `.md`。只链接已经存在的题目；检查脚本会报告不存在的链接。相关但不在本题展开的内容，用一句话加链接带过，避免各题重复。

## 安全相关的题

讲攻击是为了讲清防御。攻击手法只描述原理和类别，不给可以直接拿去用的攻击载荷或越狱提示词。
